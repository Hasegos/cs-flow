스택 / 큐

태그

스택(Stack)과 큐(Queue)는 데이터 삽입·삭제 순서를 제한하는 선형 자료구조입니다. 스택은 마지막에 넣은 데이터를 먼저 꺼내고(LIFO), 큐는 먼저 넣은 데이터를 먼저 꺼냅니다(FIFO).

핵심 개념

스택 — LIFO

Last In, First Out. 책을 쌓아 올린 구조를 떠올리면 됩니다. 가장 위에 올린 책을 먼저 꺼냅니다. Push로 쌓고 Pop으로 꺼내며, 항상 top 위치에서만 연산이 일어납니다. 삽입·삭제 모두 O(1)입니다.

핵심 개념

큐 — FIFO

First In, First Out. 줄 서기와 같습니다. 먼저 줄 선 사람이 먼저 나갑니다. Enqueue로 rear에 추가하고 Dequeue로 front에서 꺼냅니다. 삽입·삭제 모두 O(1)이며, front와 rear 두 포인터를 관리합니다.

핵심 개념

스택의 활용

함수 호출 스택(Call Stack), 브라우저 뒤로가기, 괄호 유효성 검사, DFS 탐색, 수식 계산(후위 표기법), 실행 취소(Undo) 기능이 스택 기반입니다. JVM의 스택 프레임도 스택 구조로 동작합니다.

핵심 개념

큐의 활용

OS 프로세스 스케줄링, 프린터 대기열, BFS 탐색, 메시지 큐(Kafka, RabbitMQ), 이벤트 루프(JavaScript), 네트워크 패킷 버퍼가 큐 기반입니다. 순서 보장이 필요한 모든 작업 대기열에 활용됩니다.

핵심 개념

원형 큐 (Circular Queue)

일반 배열 큐는 Dequeue 후 앞 공간이 낭비됩니다. 원형 큐는 인덱스를 (index + 1) % capacity로 순환시켜 공간을 재활용합니다. front == rear이면 빈 큐, (rear + 1) % capacity == front이면 가득 찬 상태입니다.

핵심 개념

덱 (Deque)

Double-Ended Queue. 양쪽 끝에서 삽입·삭제가 모두 가능합니다. 스택과 큐를 동시에 구현할 수 있습니다. Java의 ArrayDeque가 대표적이며, LinkedList보다 캐시 효율이 좋아 Stack/Queue 구현에 ArrayDeque를 권장합니다.

Stack Overflow / Underflow — 스택이 가득 찬 상태에서 Push하면 Stack Overflow, 빈 상태에서 Pop하면 Underflow가 발생합니다. Java의 Stack은 동기화 오버헤드가 있어 단일 스레드에서는 Deque(ArrayDeque)를 사용하는 것이 권장됩니다.
Java에서의 선택 — Stack 클래스는 Vector를 상속해 모든 메서드가 synchronized됩니다. 단일 스레드 환경에서는 ArrayDeque를 Deque 인터페이스로 사용하세요. 큐도 LinkedList보다 ArrayDeque가 메모리 지역성이 높아 더 빠릅니다.
우선순위 큐 (PriorityQueue) — 일반 큐와 달리 삽입 순서가 아닌 우선순위에 따라 꺼냅니다. 내부적으로 힙(Heap) 자료구조로 구현됩니다. Dequeue 시 O(log n), 최솟값(또는 최댓값) 조회는 O(1)입니다. 다익스트라, 프림 알고리즘에 사용됩니다.
모노토닉 스택 (Monotonic Stack) — 스택 내부 원소가 단조 증가 또는 단조 감소를 유지하는 스택입니다. 다음 큰 원소 찾기, 히스토그램 최대 직사각형 등 O(n) 풀이에 활용됩니다. 코딩 테스트에서 자주 등장하는 패턴입니다.
