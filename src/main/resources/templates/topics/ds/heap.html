힙

태그

힙(Heap)은 완전 이진 트리 기반의 자료구조로, 부모 노드가 항상 자식 노드보다 크거나(Max-Heap) 작은(Min-Heap) 조건을 만족합니다. 최댓값 또는 최솟값을 O(1)에 조회하고 O(log n)에 삽입·삭제할 수 있어 우선순위 큐의 핵심 구현체로 사용됩니다.

핵심 개념

힙 조건 (Heap Property)

Max-Heap: 모든 부모 노드의 값 ≥ 자식 노드의 값. 루트가 전체 최댓값입니다. Min-Heap: 모든 부모 노드의 값 ≤ 자식 노드의 값. 루트가 최솟값입니다. BST와 달리 형제 노드 사이에는 대소 관계가 없습니다.

핵심 개념

완전 이진 트리와 배열 표현

힙은 완전 이진 트리(마지막 레벨을 제외하고 모두 채워진 트리, 마지막 레벨은 왼쪽부터 채움)입니다. 배열로 표현할 때 인덱스 i의 왼쪽 자식은 2i+1, 오른쪽 자식은 2i+2, 부모는 (i-1)/2입니다.

핵심 개념

삽입 — Heapify-Up

새 원소를 배열 끝(트리의 마지막 위치)에 추가한 뒤, 부모와 비교하며 힙 조건을 만족할 때까지 위로 올립니다. 최대 트리 높이(log n)번 스왑이 발생하므로 O(log n)입니다.

핵심 개념

삭제 — Heapify-Down

루트(최댓값)를 제거하고 배열 마지막 원소를 루트로 이동합니다. 이후 두 자식 중 더 큰 자식과 비교하며 힙 조건을 만족할 때까지 아래로 내립니다. 마찬가지로 O(log n)입니다.

핵심 개념

힙 정렬 (Heap Sort)

① 배열을 Max-Heap으로 만들고 ② 루트(최댓값)를 배열 끝으로 이동한 뒤 힙 크기를 줄이고 Heapify-Down을 반복합니다. n번의 Extract-Max로 오름차순 정렬이 완성됩니다. 시간복잡도 O(n log n), 추가 메모리 O(1)의 제자리 정렬입니다.

핵심 개념

우선순위 큐와 Java PriorityQueue

Java의 PriorityQueue는 Min-Heap 기반입니다. peek()으로 최솟값을 O(1)에 조회, offer()로 O(log n) 삽입, poll()로 O(log n) 삭제. Max-Heap이 필요하면 Collections.reverseOrder()나 람다 Comparator를 사용합니다.

시간복잡도 — peek(최댓값 조회) O(1), offer(삽입) O(log n), poll(삭제) O(log n). Build-Heap(n개 원소로 힙 구성)은 O(n). 힙 정렬 전체는 O(n log n).
힙 vs BST — 힙은 최댓값/최솟값 접근에 특화되어 있고 배열로 표현해 캐시 효율이 좋습니다. BST는 임의 원소 탐색과 정렬 순서 접근이 가능합니다. 우선순위 큐는 힙, 정렬 유지가 필요한 맵/셋은 BST(TreeMap/TreeSet)가 적합합니다.
힙 정렬 vs 다른 정렬 — Quick Sort는 평균 O(n log n)이지만 최악 O(n²). Merge Sort는 O(n log n)이지만 추가 메모리 O(n) 필요. Heap Sort는 최악도 O(n log n)이고 추가 메모리 O(1)이나, 캐시 지역성이 낮아 실제 성능은 Quick Sort보다 느린 경우가 많습니다.
활용 사례 — 다익스트라 최단 경로(최소 비용 노드 추출), 프림 MST 알고리즘, 운영체제 CPU 스케줄링(우선순위 기반), K번째 최댓값/최솟값 탐색, 실시간 중앙값 유지(Max-Heap + Min-Heap 조합).
