해시 테이블

태그

해시 테이블(Hash Table)은 키(Key)를 해시 함수로 변환해 배열 인덱스에 직접 매핑하는 자료구조입니다. 평균 O(1)의 삽입·탐색·삭제를 제공하며, 대부분의 언어에서 딕셔너리·맵의 내부 구현으로 사용됩니다.

핵심 개념

해시 함수

임의 크기의 키를 고정 범위의 정수(해시값)로 변환합니다. 좋은 해시 함수는 결정론적(같은 입력 → 같은 출력), 균등 분포, 빠른 계산 속도를 갖춥니다. 일반적으로 hash(key) % capacity로 버킷 인덱스를 결정합니다.

핵심 개념

충돌(Collision)

서로 다른 두 키가 동일한 해시 인덱스로 매핑되는 현상입니다. 비둘기집 원리에 의해 키 공간이 배열 크기보다 크면 충돌은 반드시 발생합니다. 충돌 해결 방법으로 체이닝(Chaining)과 오픈 어드레싱(Open Addressing)이 있습니다.

핵심 개념

체이닝 (Chaining)

같은 버킷에 충돌한 키들을 연결 리스트로 연결합니다. 버킷이 연결 리스트의 헤드를 가리킵니다. 삽입은 O(1)이고 탐색은 버킷의 리스트 길이에 비례합니다. Java의 HashMap이 이 방식을 사용하며, 한 버킷의 길이가 8 이상이고 전체 용량이 64 이상일 때 트리(Red-Black Tree)로 전환합니다.

핵심 개념

오픈 어드레싱 (Open Addressing)

충돌 시 다른 빈 버킷을 탐색합니다. Linear Probing은 index+1, +2, ...를 순서대로 탐색합니다. Quadratic Probing은 index+1², +2², ...으로 탐색합니다. Double Hashing은 두 번째 해시 함수로 보폭을 결정합니다. 메모리 지역성이 좋아 캐시 효율이 높습니다.

핵심 개념

부하율 (Load Factor)

저장된 항목 수 / 버킷 수로 계산합니다. 부하율이 높을수록 충돌이 잦아져 성능이 O(n)에 가까워집니다. Java HashMap의 기본 부하율은 0.75로, 이를 초과하면 배열을 2배로 늘리고 전체를 재해싱(Rehashing)합니다.

핵심 개념

삭제와 Tombstone

오픈 어드레싱에서 단순 삭제(null 처리)는 탐색 체인을 끊어 이후 항목을 찾지 못하게 합니다. 이를 방지하기 위해 삭제된 슬롯에 Tombstone(묘비) 마커를 남겨 탐색은 계속하되 삽입 시에는 재사용합니다. 체이닝에서는 이 문제가 없습니다.

시간복잡도 — 평균 O(1) 삽입·탐색·삭제. 최악(모든 키가 같은 버킷)은 O(n). 좋은 해시 함수와 적절한 부하율 유지로 최악 케이스를 실질적으로 방지합니다. Java HashMap은 트리 전환으로 최악을 O(log n)으로 제한합니다.
Java HashMap 내부 구조 — 기본 용량 16, 부하율 0.75, 임계값 초과 시 2배 리사이징. 버킷당 연결 리스트 길이 ≥ 8이고 전체 용량 ≥ 64면 Red-Black Tree로 전환, 길이 ≤ 6이면 다시 리스트로 전환합니다. hashCode()와 equals()를 반드시 함께 재정의해야 합니다.
해시 충돌 공격 — 악의적 입력으로 모든 키를 동일 버킷에 몰아 O(n) 성능을 유발하는 공격입니다. Java는 해시 무작위화 대신, 한 버킷의 체인이 길어지면(길이 ≥ 8, 전체 용량 ≥ 64) Red-Black Tree로 전환해 최악을 O(log n)으로 막습니다(JEP 180, Java 8+). 반면 파이썬은 3.3부터 SipHash 기반 해시 무작위화가 기본 활성화되어 있습니다.
언제 해시 테이블을 쓰나 — 키-값 쌍 저장, 중복 제거, 빈도 카운팅, 캐시(LRU 구현), 두 컬렉션의 교집합·차집합 계산. 순서 보장이 필요하면 Java LinkedHashMap(삽입 순서) 또는 TreeMap(정렬 순서)을 사용합니다.
