접미사 배열

태그

긴 문자열에서 "이 패턴이 어디에 나오는가?"를 여러 번 물어야 할 때, 질문마다 문자열 전체를 훑으면 비효율적입니다. 문자열을 미리 정리해 두면 질문마다 훨씬 빠르게 답할 수 있습니다. 접미사 배열(suffix array)은 문자열의 모든 접미사를 사전순으로 정렬했을 때 각 접미사가 시작하는 인덱스를 차례로 적어 둔 배열로, 이 정렬 덕분에 패턴 검색을 이진 탐색으로 할 수 있습니다.

예를 들어 "banana"의 접미사는 banana, anana, nana, ana, na, a이고, 이를 사전순으로 정렬하면 a, ana, anana, banana, na, nana입니다. 각각의 시작 인덱스를 모은 [5, 3, 1, 0, 4, 2]가 접미사 배열입니다. 접미사 문자열을 모두 저장하지 않고 인덱스 n개만 저장하므로 공간이 O(n)입니다. 이웃한 접미사의 공통 접두사 길이를 담은 LCP 배열을 함께 쓰면 가장 긴 반복 부분 문자열 같은 문제도 풀 수 있습니다.

핵심 개념

접미사

문자열의 i번째 글자부터 끝까지입니다. 길이 n인 문자열에는 접미사가 n개 있고, 인덱스 i가 접미사 하나를 대표합니다.

핵심 개념

접미사 배열

접미사를 사전순으로 정렬했을 때 시작 인덱스를 순서대로 적은 배열입니다. SA[r]은 순위(0부터) r인 접미사가 시작하는 위치입니다.

핵심 개념

패턴 검색

패턴으로 시작하는 접미사들은 정렬된 배열에서 연속된 구간을 이룹니다. 이진 탐색으로 구간의 시작과 끝을 찾으면 구간의 SA 값이 모두 출현 위치입니다.

핵심 개념

LCP 배열

사전순으로 이웃한 두 접미사가 앞에서부터 몇 글자까지 같은지(최장 공통 접두사)를 적은 배열입니다. 정렬하면 같은 접두사를 가진 접미사끼리 이웃하므로, 임의의 두 접미사의 공통 접두사 길이는 그 사이 구간 LCP의 최솟값으로 구할 수 있습니다.

핵심 개념

구성 알고리즘

접미사를 비교 정렬하면 단순하지만 느리고, 접두사를 두 배씩 늘려 가며 기수(계수) 정렬로 순위를 매기는 방식은 O(n log n), 선형 시간 알고리즘은 O(n)에 접미사 배열을 만듭니다.

핵심 개념

접미사 트리와의 관계

접미사 트리가 하는 일의 상당 부분을 접미사 배열과 LCP 배열이 더 적은 메모리로 해냅니다. 구조가 정렬된 배열과 이진 탐색이라 단순하지만, 선형 시간 구성 알고리즘은 복잡합니다.

검색은 이진 탐색으로 합니다 — 패턴 길이를 m이라 하면 비교 한 번에 최대 m글자를 보므로 구간의 시작과 끝을 찾는 데 대략 O(m log n)이 듭니다. 패턴이 텍스트보다 훨씬 짧으면, 같은 문자열을 여러 번 검색할 때 매번 O(n)씩 훑는 것보다 빠릅니다.
공간이 O(n)입니다 — 접미사를 문자열로 저장하지 않고 정수 인덱스만 저장합니다. 접미사를 모두 저장하면 O(n^2)가 됩니다.
전처리 비용을 한 번 치릅니다 — 구성에 시간이 들지만, 한 번 만들면 같은 문자열에 대한 많은 질문에 재사용합니다. 문자열이 바뀌면 보통 다시 만듭니다.
LCP로 통계를 얻습니다 — LCP의 최댓값이 가장 긴 반복 부분 문자열의 길이이고, n(n + 1) / 2에서 LCP의 합을 빼면 서로 다른 부분 문자열의 개수입니다.
이 시각화에서 확인할 것 — "구성" 탭에서 접미사가 사전순으로 놓이는 과정을, "패턴 검색" 탭에서 이진 탐색이 구간의 시작과 끝을 좁혀 가는 모습을, "LCP 배열" 탭에서 이웃한 접미사의 공통 접두사를 STEP으로 확인하세요.

접미사 배열의 배경

접미사 배열은 우디 매버(Udi Manber)와 진 마이어스(Gene Myers)가 1990년 소개했고, 이후 1993년 학술지에 "Suffix arrays: a new method for on-line string searches"로 실렸습니다. 접미사 트리보다 메모리를 적게 쓰면서 온라인 문자열 검색을 효율적으로 하자는 것이 목표였습니다. 이후 선형 시간에 구성하는 알고리즘(Kärkkäinen과 Sanders, Ko와 Aluru 등)과 LCP 배열을 선형 시간에 구하는 Kasai 등의 알고리즘이 나와, 접미사 배열과 LCP 배열을 모두 선형 시간에 만들 수 있게 되었습니다.

숫자로 확인하기

구성 — "banana"의 접미사 6개를 사전순으로 정렬하면 a(5), ana(3), anana(1), banana(0), na(4), nana(2)이고, 접미사 배열은 [5, 3, 1, 0, 4, 2]입니다.
검색 — 패턴 "ana"는 이진 탐색으로 구간 [1, 3)을 찾고, 그 구간의 SA 값 3과 1이 출현 위치입니다. 실제로 "banana"의 1번과 3번 위치에서 "ana"가 시작합니다.
LCP 배열 — 이웃한 접미사의 공통 접두사 길이는 [0, 1, 3, 0, 0, 2]입니다. 최댓값 3이 가리키는 문자열이 "ana"입니다.
서로 다른 부분 문자열 — "banana"는 21 - 6 = 15개입니다. "mississippi"는 가장 긴 반복 부분 문자열이 "issi", 서로 다른 부분 문자열이 53개로, 모든 부분 문자열을 직접 모아 센 값과 같았습니다.

자주 하는 오해

접미사 배열이 접미사 문자열을 저장한다 — 인덱스만 저장하고 문자열은 원본을 그대로 씁니다. 그래서 공간이 O(n)입니다.
단순 정렬이면 충분하다 — 접미사를 비교하는 데 최대 O(n)이 걸려서 정렬 전체가 O(n^2 log n)까지 갈 수 있습니다. 긴 문자열에는 전용 구성 알고리즘을 씁니다.
접미사 트리의 완전한 대체이다 — 많은 문제를 접미사 배열과 LCP 배열로 풀 수 있지만, 일부 연산은 접미사 트리가 더 직접적입니다. 메모리가 중요하면 접미사 배열을 고릅니다.
문자열이 바뀌어도 쉽게 갱신된다 — 문자열을 수정하면 접미사의 순서가 바뀌므로 다시 만드는 것이 보통입니다. 한 번 만들고 여러 번 질의하는 상황에 알맞습니다.

면접에서 이렇게 물어요

면접 질문

접미사 배열이란 무엇인가요?

문자열의 모든 접미사를 사전순으로 정렬했을 때 각 접미사가 시작하는 인덱스를 저장한 배열입니다. 접미사 문자열이 아니라 인덱스만 저장해 공간이 O(n)입니다.

면접 질문

패턴 검색은 어떻게 하나요?

정렬되어 있으므로 패턴으로 시작하는 접미사들이 연속된 구간을 이룹니다. 이진 탐색으로 구간의 시작과 끝을 찾고, 그 구간의 SA 값이 출현 위치입니다.

면접 질문

LCP 배열은 어디에 쓰나요?

이웃한 접미사의 최장 공통 접두사 길이로, 가장 긴 반복 부분 문자열과 서로 다른 부분 문자열의 개수 계산에 씁니다. 후자는 n(n + 1) / 2에서 LCP의 합을 뺍니다.

면접 질문

접미사 트리와 비교하면?

접미사 배열은 보통 메모리를 적게 쓰고(원 논문은 실제 구현에서 3~5배 적다고 보고) 구조가 단순합니다. 접미사 트리는 일부 연산이 더 직접적이지만 메모리와 구현 부담이 큽니다.

실제 시스템에서는

생물정보학 — 긴 유전체 서열에서 짧은 서열이 어디에 나오는지 찾는 문제에서 BWA, Bowtie 같은 도구가 BWT 기반 FM 인덱스를 씁니다. FM 인덱스는 접미사 배열처럼 패턴의 출현 구간을 찾되 압축된 공간에 담은 구조입니다.
데이터 압축 — 버로스-휠러 변환(BWT)은 문자열의 회전을 정렬한 결과를 이용하는데, 문자열 끝에 종료 기호를 붙이면 회전 정렬과 접미사 정렬의 순서가 같아서 접미사 배열 SA에서 BWT[i] = T[SA[i] - 1]로 얻을 수 있습니다. bzip2 압축에 BWT가 쓰입니다.
알고리즘 대회 — 가장 긴 반복 부분 문자열, 서로 다른 부분 문자열 수, 두 문자열의 가장 긴 공통 부분 문자열 같은 문제에 자주 쓰는 도구입니다.

함께 보면 좋은 토픽

이진 탐색 — 접미사 배열 검색이 쓰는 이진 탐색의 원리를 봅니다.
트라이 — 문자열을 접두사 트리로 저장하는 구조와 비교합니다.
정렬 비교 — 접미사를 정렬하는 비용을 이해하는 데 도움이 됩니다.
시간 복잡도 — O(n log n)과 O(n^2 log n)의 차이를 봅니다.
