스택 / 큐

태그

스택(Stack)과 큐(Queue)는 데이터 삽입·삭제 순서를 제한하는 선형 자료구조입니다. 스택은 마지막에 넣은 데이터를 먼저 꺼내고(LIFO), 큐는 먼저 넣은 데이터를 먼저 꺼냅니다(FIFO).

핵심 개념

스택 — LIFO

Last In, First Out. 책을 쌓아 올린 구조를 떠올리면 됩니다. 가장 위에 올린 책을 먼저 꺼냅니다. Push로 쌓고 Pop으로 꺼내며, 항상 top 위치에서만 연산이 일어납니다. 삽입·삭제 모두 O(1)입니다.

핵심 개념

큐 — FIFO

First In, First Out. 줄 서기와 같습니다. 먼저 줄 선 사람이 먼저 나갑니다. Enqueue로 rear에 추가하고 Dequeue로 front에서 꺼냅니다. 삽입·삭제 모두 O(1)이며, front와 rear 두 포인터를 관리합니다.

핵심 개념

스택의 활용

함수 호출 스택(Call Stack), 브라우저 뒤로가기, 괄호 유효성 검사, DFS 탐색, 수식 계산(후위 표기법), 실행 취소(Undo) 기능이 스택 기반입니다. JVM의 스택 프레임도 스택 구조로 동작합니다.

핵심 개념

큐의 활용

OS 프로세스 스케줄링, 프린터 대기열, BFS 탐색, 메시지 큐(RabbitMQ 같은 메시징 시스템), 이벤트 루프(JavaScript), 네트워크 패킷 버퍼가 큐 기반입니다. 순서 보장이 필요한 모든 작업 대기열에 활용됩니다.

핵심 개념

원형 큐 (Circular Queue)

일반 배열 큐는 Dequeue 후 앞 공간이 낭비됩니다. 원형 큐는 인덱스를 (index + 1) % capacity로 순환시켜 공간을 재활용합니다. 한 칸을 비워 두는 방식에서는 front == rear이면 빈 큐, (rear + 1) % capacity == front이면 가득 찬 상태입니다.

핵심 개념

덱 (Deque)

Double-Ended Queue. 양쪽 끝에서 삽입·삭제가 모두 가능합니다. 스택과 큐를 동시에 구현할 수 있습니다. Java의 ArrayDeque가 대표적이며, Java 문서는 ArrayDeque가 스택으로 쓸 때 Stack보다, 큐로 쓸 때 LinkedList보다 빠를 가능성이 높다고 설명합니다.

Stack Overflow / Underflow — 스택이 가득 찬 상태에서 Push하면 Stack Overflow, 빈 상태에서 Pop하면 Underflow가 발생합니다. Java 문서는 Stack 대신 Deque 구현을 쓰라고 안내합니다.
Java에서의 선택 — Stack 클래스는 Vector를 상속하고 Vector의 메서드는 동기화되어 있습니다. 단일 스레드 환경에서는 ArrayDeque를 Deque 인터페이스로 사용하세요. 큐로 쓸 때도 ArrayDeque가 LinkedList보다 빠를 가능성이 높습니다.
우선순위 큐 (PriorityQueue) — 일반 큐와 달리 삽입 순서가 아닌 우선순위에 따라 꺼냅니다. 내부적으로 힙(Heap) 자료구조로 구현됩니다. Dequeue 시 O(log n), 최솟값(또는 최댓값) 조회는 O(1)입니다. 다익스트라, 프림 알고리즘에 사용됩니다.
모노토닉 스택 (Monotonic Stack) — 스택 내부 원소가 단조 증가 또는 단조 감소를 유지하는 스택입니다. 다음 큰 원소 찾기, 히스토그램 최대 직사각형 등 O(n) 풀이에 활용됩니다. 코딩 테스트에서 자주 등장하는 패턴입니다.

스택과 큐가 쓰이는 곳

스택과 큐는 데이터를 넣고 꺼내는 순서를 제한한 자료구조입니다. 이 제한 덕분에 연산이 단순해지고, 함수 호출, 작업 대기열, 그래프 탐색처럼 순서가 곧 의미인 문제에 바로 맞습니다.

숫자로 확인하기

원형 큐의 사용 가능 칸 — 한 칸을 비워 두는 방식(front == rear이면 빈 큐, (rear + 1) % capacity == front이면 가득 참)에서는 용량 8짜리 배열에 7개까지만 담깁니다. 가득 찬 것과 빈 것을 구별하려고 한 칸을 쓰지 않기 때문입니다.
괄호 검사 예 — 문자열 {[()]}를 왼쪽부터 읽으면 스택 깊이가 1 → 2 → 3으로 올라갔다가 닫는 괄호마다 하나씩 줄어 0이 되어 끝납니다. 끝날 때 스택이 비어 있으면 올바른 괄호입니다.
모노토닉 스택의 비용 — 각 원소가 한 번 들어가고 최대 한 번 나오므로 전체 시간이 O(n)입니다. 이중 반복문이면 O(n²)이어서 n = 100,000일 때 약 50억 번 대 10만 번 수준의 차이입니다.

자주 하는 오해

Java에서는 Stack 클래스를 쓰는 게 기본이다 — 문서가 Stack 대신 Deque 구현을 쓰라고 안내합니다. Stack은 Vector를 상속해 오래된 설계의 흔적이 남아 있습니다.
큐는 LinkedList로 만드는 게 정석이다 — Java 문서는 ArrayDeque가 큐로 쓸 때 LinkedList보다 빠를 가능성이 높다고 설명합니다.
원형 큐는 항상 한 칸을 비운다 — 비우는 방식은 한 가지 구현 방법입니다. 원소 개수를 따로 세는 변수를 두면 모든 칸을 쓸 수 있습니다.
우선순위 큐도 FIFO다 — 우선순위 큐는 넣은 순서가 아니라 우선순위가 높은 것부터 꺼냅니다. 같은 우선순위끼리의 순서는 구현이 보장하지 않을 수 있습니다.

면접에서 이렇게 물어요

면접 질문

스택 두 개로 큐를 만들려면 어떻게 하나요?

한 스택에 넣고, 꺼낼 때 두 번째 스택이 비어 있으면 첫 스택의 원소를 모두 옮긴 뒤 두 번째에서 꺼냅니다. 각 원소는 첫 스택에 한 번 넣어지고, 옮겨질 때 한 번 꺼내져 두 번째 스택에 넣어지며, 두 번째에서 한 번 꺼내집니다. n번 연산의 총비용이 O(n)이라 연산당 분할 상환 O(1)입니다.

면접 질문

괄호 유효성 검사를 어떻게 하나요?

여는 괄호는 스택에 넣고, 닫는 괄호를 만나면 꼭대기와 짝이 맞는지 확인하며 꺼냅니다. 끝에 스택이 비어 있어야 올바른 문자열입니다.

면접 질문

스택 오버플로는 언제 발생하나요?

스택 용량이 찼는데 push할 때입니다. 함수 호출 스택에서는 재귀가 너무 깊어질 때 발생하고, Java는 StackOverflowError를 던집니다.

면접 질문

우선순위 큐는 어떻게 구현하나요?

보통 힙으로 구현해 삽입과 최솟값 꺼내기가 O(log n)이고 최솟값 조회는 O(1)입니다. Java의 PriorityQueue도 힙 기반입니다.

실제 시스템에서는

Java Deque — Deque 문서는 LIFO 스택 연산을 더 완전하고 일관되게 제공한다며 Stack 클래스보다 Deque를 쓰라고 안내합니다. ArrayDeque는 스택으로 쓸 때 Stack보다, 큐로 쓸 때 LinkedList보다 빠를 가능성이 높다고 설명합니다.
함수 호출 스택 — 호출될 때마다 스택 프레임이 쌓이고 반환하면 사라집니다. 너무 깊은 재귀는 StackOverflowError를 일으킵니다.
메시징 시스템 — Kafka나 RabbitMQ 같은 시스템은 메시지를 큐처럼 순서대로 전달하는 구조를 제공합니다. 다만 각 시스템의 보장 범위(파티션 단위 순서 등)는 다르니 문서를 확인해야 합니다.
