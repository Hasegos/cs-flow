DHCP

태그

노트북을 카페 와이파이에 연결하거나 스마트폰을 새 공유기에 붙이면, 따로 설정하지 않아도 곧바로 인터넷을 쓸 수 있습니다. 네트워크에서 통신하려면 IP 주소, 서브넷 마스크, 기본 게이트웨이, DNS 서버 주소 같은 설정이 필요한데, 장치마다 이를 손으로 입력하게 하면 번거롭고 주소가 겹치는 실수도 생깁니다. 이 설정을 서버가 대신 나눠 주는 프로토콜이 DHCP(Dynamic Host Configuration Protocol)입니다. DHCP 서버는 사용할 수 있는 주소 범위(풀)를 가지고 있다가, 요청한 장치에 주소 하나를 정해진 기간 동안 빌려 줍니다(임대, lease).

흥미로운 점은 DHCP를 받는 시점의 클라이언트에게 IP 주소도, 서버가 어디 있는지도 없다는 것입니다. 그래서 첫 메시지는 브로드캐스트로 보내야 합니다. 이 토픽에서는 주소를 받는 네 단계(Discover → Offer → Request → Acknowledge, 앞 글자를 따 DORA), 임대 시간이 지나기 전 연장하는 방법(갱신 T1과 재바인딩 T2), 서버가 주소와 함께 알려 주는 설정 항목을 단계별로 봅니다.

핵심 개념

DHCP 서버와 주소 풀

서버가 나눠 줄 수 있는 주소의 범위(풀)를 관리합니다. 클라이언트의 요청에 풀에서 주소를 골라 설정과 함께 제안하고, 누구에게 빌려 줬는지를 기록합니다.

핵심 개념

DORA 4단계

클라이언트가 서버를 찾는 Discover, 서버의 제안인 Offer, 클라이언트가 제안을 받아들이는 Request, 서버가 확정하는 Acknowledge로 이루어집니다. 이 네 단계가 끝나면 주소를 쓸 수 있습니다.

핵심 개념

브로드캐스트로 시작

처음에는 클라이언트의 IP가 0.0.0.0이고 서버 위치도 몰라서, Discover를 목적지 255.255.255.255로 브로드캐스트합니다. DHCP는 UDP를 쓰며 서버는 포트 67, 클라이언트는 포트 68을 씁니다.

핵심 개념

임대(lease)

주소는 영구 할당이 아니라 정해진 시간 동안 빌려 주는 것입니다. 쓰지 않는 장치의 주소는 임대가 끝나면 다시 풀로 돌아가 다른 장치가 쓸 수 있습니다.

핵심 개념

갱신(T1)과 재바인딩(T2)

기본값으로 임대 시간의 50%가 지나면 원래 서버에게 연장을 요청하고(T1), 응답이 없으면 87.5%에서 아무 서버에게나 브로드캐스트로 요청합니다(T2). 끝까지 연장하지 못하면 주소를 포기합니다.

핵심 개념

DHCP 옵션

IP 주소 외의 설정은 메시지의 옵션 필드에 담깁니다. 서브넷 마스크(옵션 1), 게이트웨이(옵션 3), DNS 서버(옵션 6), 임대 시간(옵션 51), 서버 식별자(옵션 54) 같은 것들입니다.

설정을 자동으로 받습니다 — IP 주소뿐 아니라 게이트웨이와 DNS까지 한 번에 받아 곧바로 통신할 수 있습니다.
첫 요청은 브로드캐스트입니다 — IP도 서버 위치도 모르는 상태에서 서버를 찾아야 하므로 Discover는 같은 LAN 전체에 보냅니다.
처음 받을 때 Request도 브로드캐스트입니다 — 서버가 여러 대일 수 있어, 어느 서버의 제안을 골랐는지 모든 서버가 알게 합니다. 갱신 요청은 원래 서버에 유니캐스트로 보냅니다.
주소는 빌려 쓰는 것입니다 — 임대 시간 안에 연장하지 않으면 주소를 잃고 처음부터 다시 받습니다.
이 시각화에서 확인할 것 — "DORA 4단계" 탭에서 주소를 받는 과정을, "임대와 갱신" 탭에서 T1 · T2 · 만료를, "할당 정보" 탭에서 서버가 알려 주는 설정 항목을 STEP으로 확인하세요.

DHCP의 배경

DHCP는 RFC 2131(1997)로 정의되었고, 이보다 앞선 부트스트랩 프로토콜 BOOTP를 확장한 것입니다. BOOTP가 정해 둔 메시지 형식을 바탕으로 하면서, 주소를 한 번 고정해 주는 대신 풀에서 동적으로 빌려 주고 임대를 갱신하는 기능을 더했습니다. 옵션의 종류는 RFC 2132에 정리되어 있습니다. IPv6에서는 DHCPv6(RFC 8415)나 라우터 광고를 이용한 자동 설정(SLAAC)이 쓰입니다.

숫자로 확인하기

포트와 목적지 — 서버는 UDP 포트 67, 클라이언트는 UDP 포트 68을 씁니다. 첫 Discover는 출발지 0.0.0.0:68에서 목적지 255.255.255.255:67로 갑니다.
메시지 수 — 처음 주소를 받는 데는 Discover, Offer, Request, Acknowledge 4개의 메시지가 오갑니다.
임대 시간 예시 — 임대 시간이 8시간(28,800초)이면 기본 T1은 8 × 0.5 = 4시간, 기본 T2는 8 × 0.875 = 7시간입니다. 서버가 같은 임대 시간으로 응답하면 4시간 시점부터 새 8시간이 시작됩니다(길이는 서버 정책에 따름).
예시 설정 — 이 시각화에서는 주소 풀에서 192.168.0.105를 받고, 서브넷 마스크 255.255.255.0, 게이트웨이 192.168.0.1, DNS 8.8.8.8을 함께 받습니다.

자주 하는 오해

DHCP는 IP 주소만 준다 — 서브넷 마스크, 기본 게이트웨이, DNS 서버 주소, 임대 시간 같은 설정도 함께 알려 줍니다.
한 번 받은 IP는 계속 내 것이다 — 임대 시간 동안만 빌려 쓰는 주소입니다. 연장하지 못하면 사용을 멈춰야 합니다. 서버가 같은 클라이언트에 같은 주소를 다시 주는 경우가 많지만 보장은 아닙니다.
DHCP 서버는 라우터를 건널 수 없다 — 브로드캐스트는 라우터를 넘지 않지만, 라우터가 DHCP 릴레이 에이전트 기능으로 요청을 서버에 전달하면 다른 네트워크의 서버도 쓸 수 있습니다.
DHCP와 DNS는 같은 일을 한다 — DHCP는 장치에 IP 주소와 설정을 나눠 주고, DNS는 이름을 IP 주소로 바꿉니다. DHCP가 DNS 서버의 주소를 알려 주는 관계입니다.

면접에서 이렇게 물어요

면접 질문

DHCP가 IP를 할당하는 과정을 설명해 주세요

클라이언트가 Discover를 브로드캐스트하면 서버가 Offer로 주소를 제안하고, 클라이언트가 Request로 수락하면 서버가 Acknowledge로 확정합니다. 앞 글자를 따 DORA라고 합니다.

면접 질문

Discover를 왜 브로드캐스트로 보내나요?

이 시점의 클라이언트는 자기 IP 주소도, DHCP 서버의 위치도 모르기 때문입니다. 같은 네트워크 전체에 보내 응답할 서버를 찾습니다.

면접 질문

DHCP가 IP 외에 알려 주는 정보는 무엇인가요?

서브넷 마스크, 기본 게이트웨이, DNS 서버 주소, 임대 시간, 서버 식별자 등이며, 이 값이 있어야 별도 설정 없이 인터넷을 쓸 수 있습니다.

면접 질문

임대 시간이 끝나면 어떻게 되나요?

임대의 절반쯤에 클라이언트가 서버에게 연장을 요청하고, 응답이 없으면 더 늦게 브로드캐스트로 요청합니다. 끝까지 연장하지 못하면 주소를 포기하고 처음부터 DORA를 다시 합니다.

실제 시스템에서는

가정용 공유기 — 대부분의 공유기에 DHCP 서버가 들어 있어 연결한 장치에 사설 주소를 나눠 줍니다.
고정 할당(예약) — 특정 MAC 주소에는 항상 같은 IP를 주도록 서버에 예약해 두면, 프린터나 서버처럼 주소가 바뀌면 곤란한 장치도 DHCP로 관리할 수 있습니다.
DHCP 릴레이 — 여러 서브넷이 있는 환경에서는 각 서브넷의 라우터가 DHCP 요청을 중앙 서버로 전달해, 서버 한 대로 여러 네트워크를 관리합니다.
클라우드와 가상 머신 — 가상 네트워크도 DHCP로 가상 머신에 주소를 나눠 주는 경우가 많습니다.

함께 보면 좋은 토픽

ARP — IP 주소를 받은 뒤 같은 LAN에서 MAC 주소를 알아내는 방법을 봅니다.
DNS — DHCP가 알려 주는 DNS 서버가 하는 일을 봅니다.
TCP/IP — UDP와 IP 위에서 메시지가 오가는 구조를 봅니다.
라우팅 — DHCP가 알려 주는 게이트웨이가 하는 일을 봅니다.
