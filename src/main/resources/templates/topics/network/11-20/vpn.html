VPN 터널링

태그

카페의 공용 와이파이에서 회사 내부 서버에 접속한다고 생각해 봅시다. 내부 서버의 주소는 사설 주소여서 인터넷에서는 닿지 않고, 암호화하지 않은 데이터를 공용 인터넷으로 보내면 중간의 네트워크 장비나 같은 와이파이를 쓰는 누군가가 내용을 볼 수 있습니다. 이 문제를 풀어 주는 것이 VPN(Virtual Private Network, 가상 사설망)입니다. VPN은 공용 인터넷 위에 암호화된 가상의 통로를 만들어, 물리적으로는 공용망을 지나면서도 논리적으로는 사설망처럼 통신하게 합니다. 이 통로를 만드는 핵심 방법이 터널링(tunneling)입니다.

터널링은 원래의 패킷(내부 패킷)을 다른 패킷 안에 넣어서(캡슐화) 보내는 방식입니다. 택배 상자를 더 큰 상자에 넣어 보내는 것과 비슷합니다. VPN에서는 내부 패킷 전체를 암호화한 뒤 새 헤더를 붙이므로, 중간 장비는 바깥 헤더만 볼 수 있을 뿐 안의 주소와 내용은 읽을 수 없습니다. 이 토픽에서는 캡슐화 과정, 노트북에서 사내 서버까지 패킷이 지나가는 여정, 그리고 VPN의 종류와 대표 방식을 단계별로 봅니다.

핵심 개념

VPN

공용 인터넷 위에 암호화된 터널을 만들어 사설망처럼 쓰게 하는 기술입니다. 원격 근무자가 회사 내부 자원에 안전하게 접속하거나, 떨어진 지사끼리 네트워크를 잇는 데 씁니다.

핵심 개념

터널링과 캡슐화

원래의 패킷을 다른 프로토콜의 패킷 안에 넣어 전달하는 방식입니다. 안쪽 패킷은 목적지에 도착해서야 꺼내지므로, 중간 장비는 바깥 패킷의 주소만 보고 전달합니다.

핵심 개념

암호화와 인증

터널 안의 데이터를 암호화해 도청을 막고, 상대가 맞는지 인증과 무결성 검사로 확인해 위조와 변조를 막습니다. 터널의 두 끝은 키를 미리 정하거나 키 교환으로 공유합니다.

핵심 개념

VPN 게이트웨이

회사나 지사의 네트워크 쪽에서 터널의 한쪽 끝을 맡는 장비입니다. 들어온 암호화 패킷을 복호화해 내부망에 넘기고, 나가는 패킷은 암호화해 터널로 내보냅니다.

핵심 개념

원격 접속과 사이트 간

개별 기기가 게이트웨이와 터널을 만드는 것이 원격 접속 VPN이고, 두 네트워크의 게이트웨이끼리 터널을 만드는 것이 사이트 간 VPN입니다. 사이트 간에서는 안쪽 기기들이 VPN을 의식하지 않고 통신합니다.

핵심 개념

IPsec · WireGuard · OpenVPN

대표적인 VPN 프로토콜입니다. IPsec은 IP 계층에서 패킷을 보호하고, WireGuard는 UDP 위에서 동작하는 간결한 방식이며, OpenVPN은 TLS를 이용합니다.

공용망 구간을 보호합니다 — 노트북에서 VPN 게이트웨이까지의 인터넷 구간에서 내용이 노출되지 않게 합니다.
안쪽 패킷은 사설 주소를 씁니다 — 내부 패킷은 사내망 주소로 가고, 바깥 패킷은 인터넷에서 통하는 공인 주소로 갑니다. 두 주소 체계가 겹쳐 있는 것이 터널링의 특징입니다.
게이트웨이 뒤 구간은 VPN으로 보호되지 않습니다 — VPN의 암호화는 노트북과 게이트웨이 사이에서만 유지되고, 게이트웨이를 지난 사내망 안에서는 원래의 패킷이 VPN의 보호 없이 전달됩니다(HTTPS 같은 응용 계층 암호화는 별개입니다).
캡슐화에는 비용이 듭니다 — 헤더가 추가되고 암·복호화를 하므로 한 패킷에 실을 수 있는 데이터 크기(MTU)가 줄고 처리 시간이 늘어납니다.
이 시각화에서 확인할 것 — "캡슐화" 탭에서 내부 패킷이 암호화되어 바깥 패킷에 담기는 과정을, "패킷의 여정" 탭에서 노트북에서 사내 서버까지의 흐름을, "종류와 방식" 탭에서 VPN의 형태와 대표 프로토콜을 STEP으로 확인하세요.

VPN의 배경

전용선을 빌려 지사를 잇던 방식은 비용이 컸고, 공용 인터넷을 쓰면서도 사설망 같은 보안을 얻으려는 필요에서 VPN이 널리 쓰이게 되었습니다. IP 계층의 보안 구조는 IPsec으로 표준화되어 있고(RFC 4301이 구조를 정의), 데이터 보호는 ESP(RFC 4303)가 맡습니다. 키 교환 프로토콜은 IKEv2(RFC 7296)입니다. 비교적 최근에는 코드 규모가 작은 WireGuard가 리눅스 커널 5.6에 포함되며 널리 쓰이고 있습니다.

숫자로 확인하기

시각화의 주소 — 내부 패킷은 VPN 가상 주소 10.8.0.2에서 사내 서버 192.168.10.5로 가고, 외부 패킷은 NAT를 거친 뒤의 노트북 공인 주소 203.0.113.20에서 게이트웨이 198.51.100.1로 갑니다. 203.0.113.0/24와 198.51.100.0/24는 문서용 주소 대역입니다.
헤더 오버헤드 — 외부 IP 헤더(IPv4는 최소 20바이트)와 VPN 헤더가 붙은 만큼 내부 패킷이 쓸 수 있는 크기가 줄어듭니다. WireGuard는 바깥 IP 헤더(IPv4 20바이트, IPv6 40바이트), UDP 8바이트, WireGuard 헤더와 인증 태그 32바이트가 붙어 IPv4에서는 60바이트, IPv6에서는 80바이트가 늘어납니다. wg-quick은 IPv6까지 감안해 기본 MTU를 인터페이스 MTU에서 80을 뺀 값으로 잡아, 이더넷 1500에서 1420이 됩니다.
단계의 수 — 캡슐화 탭은 내부 패킷 만들기, 암호화, 캡슐화, 중간 구간, 게이트웨이의 복원까지 5단계, 여정 탭은 노트북 · 인터넷 · 게이트웨이 · 서버 4개 지점을 거칩니다.

자주 하는 오해

VPN을 쓰면 인터넷이 빨라진다 — 암호화와 캡슐화, 우회 경로 때문에 지연이 늘거나 속도가 떨어질 수 있습니다. VPN의 목적은 속도가 아니라 보호와 접근입니다.
VPN을 쓰면 완전히 익명이 된다 — 터널 끝의 VPN 서버 운영자는 접속 목적지와, HTTPS 등으로 따로 보호되지 않은 내용을 볼 수 있습니다. 로그인 정보나 쿠키처럼 기기에서 식별되는 정보도 그대로입니다.
VPN을 쓰면 모든 구간이 암호화된다 — 암호화는 노트북과 VPN 게이트웨이 사이에만 적용됩니다. 게이트웨이를 지나 사내망이나 인터넷으로 나갈 때의 구간은 별도의 보호가 없으면 평문일 수 있습니다.
VPN은 악성코드를 막아 준다 — VPN은 통신 경로를 보호할 뿐, 기기가 받는 파일이나 접속하는 사이트의 안전을 보장하지 않습니다.

면접에서 이렇게 물어요

면접 질문

VPN이 무엇이고 왜 쓰나요?

공용 인터넷 위에 암호화된 터널을 만들어 사설망처럼 안전하게 통신하게 하는 기술입니다. 원격 근무자가 회사 내부 자원에 안전하게 접속하고, 지사끼리 네트워크를 이을 때 씁니다.

면접 질문

터널링(캡슐화)이란 무엇인가요?

원래의 패킷을 다른 패킷 안에 넣어 전달하는 것입니다. VPN에서는 내부 패킷을 암호화해 새 IP 헤더를 붙여 보내고, 도착한 끝점이 바깥 헤더를 벗기고 복호화해 원래 패킷을 꺼냅니다.

면접 질문

원격 접속 VPN과 사이트 간 VPN의 차이는?

원격 접속은 개별 기기가 회사 게이트웨이와 터널을 만드는 방식이고, 사이트 간은 본사와 지사의 게이트웨이끼리 터널을 만들어 두 네트워크를 잇는 방식입니다.

면접 질문

VPN만 있으면 안전한가요?

아닙니다. VPN은 터널 구간의 도청과 변조를 막을 뿐입니다. 접속 후의 접근 권한 관리, 기기 보안, 사내망 안의 보안은 따로 필요합니다.

실제 시스템에서는

WireGuard — 설정 파일에 상대의 공개키와 허용할 주소 범위(AllowedIPs)를 적으면 터널이 만들어집니다. 보통 UDP를 쓰며 포트는 설정으로 정합니다.
IPsec — 사이트 간 VPN에 널리 쓰이고, 키 교환(IKE)은 UDP 포트 500을, NAT 뒤에서는 UDP 포트 4500의 NAT 통과 방식을 씁니다.
전체 터널과 분할 터널 — 모든 트래픽을 터널로 보낼지(전체), 사내망으로 가는 트래픽만 터널로 보낼지(분할)를 라우팅(IPsec은 정책과 트래픽 셀렉터)으로 정합니다. 분할로 하면 인터넷 트래픽이 터널을 거치지 않아 부담이 줄지만, 그 구간은 VPN으로 보호되지 않습니다.
클라우드 연결 — 클라우드 사업자가 제공하는 사이트 간 VPN 서비스로 사내 네트워크와 클라우드의 가상 네트워크를 IPsec 터널로 잇는 구성이 흔합니다.

함께 보면 좋은 토픽

HTTPS와 TLS — 암호화 통신의 기본 원리와 인증서를 봅니다.
NAT — 사설 주소와 공인 주소가 오가는 방식을 봅니다.
TCP/IP — IP 헤더와 캡슐화의 기본 구조를 봅니다.
라우팅 — 터널로 보낼 트래픽을 정하는 경로 설정을 봅니다.
