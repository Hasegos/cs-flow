WebSocket

태그

WebSocket은 하나의 TCP 연결 위에서 클라이언트와 서버가 양방향으로 실시간 통신할 수 있는 프로토콜입니다. HTTP Upgrade 핸드셰이크로 연결을 수립한 뒤, 이후부터는 HTTP 오버헤드 없이 프레임 단위로 데이터를 주고받습니다.

핵심 개념

HTTP vs WebSocket

HTTP는 요청-응답 모델로, 서버가 먼저 데이터를 보낼 수 없습니다. 실시간 데이터가 필요하면 클라이언트가 계속 폴링해야 합니다. WebSocket은 연결 수립 후 양방향 채널이 열려 서버도 언제든 데이터를 푸시할 수 있습니다. 헤더 오버헤드도 없어 효율적입니다.

핵심 개념

HTTP Upgrade 핸드셰이크

WebSocket 연결은 HTTP GET 요청으로 시작합니다. 클라이언트가 Upgrade: websocket, Connection: Upgrade 헤더와 Sec-WebSocket-Key를 전송합니다. 서버가 101 Switching Protocols로 응답하면 프로토콜이 전환됩니다. 이후 HTTP는 사용하지 않습니다.

핵심 개념

WebSocket 프레임

WebSocket 데이터는 프레임 단위로 전송됩니다. 프레임 헤더는 2~10바이트로 매우 작습니다. OpCode로 Text(0x1), Binary(0x2), Ping(0x9), Pong(0xA), Close(0x8) 등을 구분합니다. 클라이언트→서버 메시지는 반드시 마스킹해야 합니다.

핵심 개념

Ping / Pong

연결 유지(Keep-alive) 메커니즘입니다. 서버가 Ping 프레임을 보내면 클라이언트는 Pong으로 응답합니다. 네트워크 장애나 클라이언트 비정상 종료를 감지하는 데 사용됩니다. Pong 응답이 없으면 서버는 연결을 닫습니다.

핵심 개념

서브프로토콜과 확장

Sec-WebSocket-Protocol 헤더로 서브프로토콜을 협상합니다. STOMP(메시지 브로커), MQTT(IoT), GraphQL-WS 등이 WebSocket 위에서 동작합니다. permessage-deflate 확장으로 메시지를 압축해 대역폭을 절약할 수 있습니다.

핵심 개념

SSE vs WebSocket

SSE(Server-Sent Events)는 서버→클라이언트 단방향 스트림으로, HTTP 위에서 동작합니다. 자동 재연결, EventSource API 등 간단한 장점이 있습니다. 단방향 알림(주식 시세, 뉴스 피드)에는 SSE가, 채팅·게임 같은 양방향 통신에는 WebSocket이 적합합니다.

폴링 vs 롱폴링 vs WebSocket — 폴링은 주기적으로 요청을 보냅니다. 롱폴링은 서버가 데이터가 생길 때까지 응답을 지연합니다. WebSocket은 연결을 유지하며 즉시 전달합니다. 동시 접속자가 많을수록 WebSocket의 효율이 압도적으로 높습니다.
Spring WebSocket + STOMP — Spring에서 @EnableWebSocketMessageBroker로 STOMP 메시지 브로커를 활성화합니다. /topic 구독으로 브로드캐스트, /queue로 1:1 메시지를 구현합니다. SockJS는 WebSocket 미지원 환경에서 폴링으로 폴백합니다.
로드 밸런서와 WebSocket — WebSocket은 장시간 연결을 유지하므로 로드 밸런서에서 Sticky Session이 필요합니다. nginx에서 proxy_http_version 1.1과 Upgrade 헤더 전달 설정이 필요합니다. Redis Pub/Sub으로 여러 서버 인스턴스 간 메시지를 전달합니다.
보안 — wss://(WebSocket Secure)는 TLS 위에서 동작합니다. CORS와 달리 WebSocket은 Origin 헤더만 있어 서버에서 반드시 Origin을 검증해야 합니다. CSRF 공격도 가능하므로 토큰 기반 인증을 사용합니다.
