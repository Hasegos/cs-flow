명령어 사이클

태그

명령어 사이클은 CPU가 하나의 명령어를 처리하기 위해 반복하는 일련의 단계입니다. 인출(Fetch) → 해독(Decode) → 실행(Execute)의 흐름이 끊임없이 반복되며, 컴퓨터가 프로그램을 실행하는 근본 동작 원리입니다.

1단계

인출 (Fetch)

PC가 가리키는 메모리 주소에서 명령어를 가져옵니다. MAR → 메모리 → MDR → IR 순서로 전달되고, PC는 자동으로 증가합니다.

2단계

해독 (Decode)

제어 유닛(CU)이 IR에 저장된 명령어를 분석합니다. 연산 코드(opcode)와 피연산자(operand)를 분리해 수행할 동작을 결정합니다.

3단계

실행 (Execute)

ALU가 산술·논리 연산을 수행하거나, 메모리 접근(LOAD/STORE)이 일어납니다. 결과는 레지스터 또는 메모리에 저장됩니다.

핵심 레지스터

PC / MAR / MDR / IR

PC는 다음 명령어 주소, MAR은 접근할 주소, MDR은 전송 데이터, IR은 현재 실행 중인 명령어를 보관합니다.

PC 자동 증가 — Fetch 단계에서 명령어를 읽는 즉시 PC가 1 증가합니다. 점프(JMP) 명령어는 이 값을 강제로 덮어씁니다.
인터럽트 체크 — Execute 완료 후 인터럽트 요청이 있으면 현재 상태를 스택에 저장하고 ISR(인터럽트 서비스 루틴)을 실행합니다.
파이프라이닝과의 관계 — 단순 사이클은 한 번에 하나의 명령어만 처리합니다. 파이프라이닝은 이 단계들을 겹쳐서 동시에 여러 명령어를 처리합니다.
MAR/MDR의 역할 — CPU와 메모리의 속도 차이를 완충하는 버퍼입니다. 모든 메모리 접근은 이 레지스터를 경유합니다.
