SIMD 벡터 연산

태그

배열의 모든 원소에 같은 계산을 하는 반복문은 흔합니다. 두 배열을 원소끼리 더하거나, 이미지의 모든 픽셀 밝기를 올리거나, 소리 샘플에 같은 배율을 곱하는 일입니다. 일반(스칼라) 명령어는 한 번에 원소 한 개만 계산하므로, 원소가 1,000개이면 덧셈 명령을 1,000번 실행합니다. SIMD(Single Instruction, Multiple Data)는 명령어 하나로 여러 데이터에 같은 연산을 동시에 적용하는 방식입니다. 폭이 넓은 벡터 레지스터에 원소 여러 개를 나란히 담고, 덧셈 한 번으로 모든 칸을 함께 더합니다. 128비트 레지스터에 32비트 float을 담으면 4개가 한 번에 계산됩니다.

SIMD라는 이름은 마이클 플린(Michael J. Flynn)이 제안한 컴퓨터 분류(SISD, SIMD, MISD, MIMD)에서 왔습니다. 개인용 컴퓨터의 CPU에서는 x86의 SSE(128비트)에서 AVX(256비트), AVX-512(512비트)로 벡터 레지스터가 넓어졌고, Arm에는 128비트 NEON과 벡터 길이가 하드웨어마다 다를 수 있는 SVE가 있습니다. 멀티코어와 달리 SIMD는 한 코어 안에서 데이터 병렬성을 쓰는 방법이며, 코드를 크게 바꾸지 않고도 컴파일러가 루프를 벡터 명령으로 바꿔 주기도 합니다.

핵심 개념

SIMD와 플린 분류

플린 분류는 명령 흐름의 수와 데이터 흐름의 수로 컴퓨터를 나눕니다. SISD는 명령 하나가 데이터 하나를, SIMD는 명령 하나가 데이터 여러 개를 처리합니다. 일반 CPU의 벡터 확장 명령이 SIMD에 해당합니다.

핵심 개념

벡터 레지스터와 레인

벡터 레지스터는 같은 크기의 원소 여러 개를 칸(레인)으로 나눠 담습니다. 레인 수는 레지스터 폭을 원소 크기로 나눈 값입니다. 128비트 레지스터에는 32비트 float이 4개, 8비트 정수가 16개 들어갑니다. 연산은 같은 위치의 레인끼리 일어납니다.

핵심 개념

명령어 집합 확장

x86에는 SSE, AVX, AVX2, AVX-512가 있고, Arm에는 NEON과 SVE가 있으며, RISC-V에는 벡터 확장(RVV)이 있습니다. CPU마다 지원하는 확장이 다르므로 컴파일 옵션이나 실행 시점의 확인으로 쓸 수 있는 명령을 정합니다.

핵심 개념

자동 벡터화와 인트린식

컴파일러가 스칼라 루프를 벡터 명령으로 바꿔 주는 것이 자동 벡터화입니다. 더 세밀하게 제어하려면 _mm_add_ps 같은 인트린식 함수로 벡터 명령을 직접 씁니다. 인트린식은 CPU 종류에 묶이는 대신, 대응하는 명령이 문서에 대부분 적혀 있어 어떤 명령이 나갈지 짐작하기 쉽습니다. 일부는 여러 명령으로 풀리고, 컴파일러가 최적화로 결과를 바꿀 수도 있습니다.

핵심 개념

마스크와 조건문

벡터 연산은 모든 레인에 같은 명령을 실행하므로 레인마다 다른 경로로 분기할 수 없습니다. 대신 비교 결과를 레인별 참/거짓 마스크로 만들고, 마스크로 결과를 고릅니다. AVX-512의 opmask 레지스터와 Arm SVE의 predicate 레지스터는 레인별로 연산을 켜고 끄는 마스크를 명령에 지정할 수 있게 합니다.

핵심 개념

나머지 처리와 메모리 정렬

배열 길이가 레인 수의 배수가 아니면 끝에 남은 원소를 따로 처리해야 합니다. 메모리 정렬도 영향을 줍니다. 예를 들어 SSE의 _mm_load_ps는 16바이트로 정렬된 주소를 요구하고, _mm_loadu_ps는 정렬을 요구하지 않습니다.

이득이 큰 곳은 규칙적인 데이터 배열입니다 — 같은 연산을 많은 원소에 반복하는 이미지·오디오 처리와 행렬 계산이 대표적입니다. 원소를 하나씩 읽는 순서가 정해져 있고 원소끼리 서로 기다리지 않을수록 잘 맞습니다.
이론상 상한은 레인 수입니다 — 레인이 4개이면 덧셈 명령 수가 최대 4분의 1이 됩니다. 실제 실행 시간은 메모리에서 데이터를 가져오는 속도와 나머지 처리 때문에 이보다 덜 줄 수 있습니다. 데이터가 도착하지 않으면 연산 폭이 넓어도 기다립니다.
앞 결과를 뒤 반복이 읽으면 벡터화할 수 없습니다 — a[i] = a[i - 1] + b[i]처럼 바로 앞 원소의 결과가 필요한 루프(루프 간 의존성)는 원소를 동시에 계산할 수 없습니다. 두 포인터가 같은 메모리를 가리킬 수 있는 경우에도 컴파일러는 안전하게 벡터화를 포기할 수 있습니다.
분기가 많거나 접근이 불규칙하면 불리합니다 — 원소마다 처리 경로가 크게 다르거나 연속되지 않은 주소를 읽는 작업은 벡터 레지스터를 채우기 어렵습니다. 흩어진 주소를 한 번에 읽는 gather 명령이 있지만 연속된 메모리를 읽을 때만큼 효율적이라고 기대하기는 어렵습니다.
이 시각화에서 확인할 것 — "스칼라 vs SIMD" 탭에서 같은 덧셈에 필요한 명령 수의 차이를, "레지스터 폭과 레인" 탭에서 폭과 원소 크기에 따라 레인 수가 달라지는 모습을, "나머지와 조건문" 탭에서 나머지 원소와 마스크 처리를 STEP으로 확인하세요.

SIMD의 배경

한 번에 여러 데이터를 처리하려는 시도는 벡터 슈퍼컴퓨터와 일리악 IV 같은 초기 SIMD 기계에서 먼저 쓰였고, 일반 CPU에는 비교적 짧은 길이의 벡터 레지스터와 전용 명령으로 들어왔습니다. 일반 CPU의 SIMD는 멀티미디어와 그래픽 처리를 빠르게 하려는 필요에서 확산됐고, 오늘날에는 과학 계산, 이미지·소리 처리, 딥러닝 라이브러리의 CPU 연산에서도 쓰입니다. Arm SVE는 벡터 폭이 바뀔 때마다 명령어 집합을 새로 만들 수 없다는 이유로 길이를 구현에 맡기고, RISC-V 벡터 확장도 벡터 길이(VLEN)가 다른 하드웨어에서 같은 프로그램이 이식 가능하게 실행되도록 설계됐습니다.

숫자로 확인하기

이 시각화의 8개 덧셈 — 스칼라 방식은 덧셈 명령이 8개이고, 128비트 SIMD(float 4레인)는 8 ÷ 4 = 2개입니다. 같은 일을 하는 덧셈 명령이 4분의 1로 줄어듭니다.
float 1,024개를 더하는 경우 — 128비트(4레인)는 1,024 ÷ 4 = 256개, 256비트(8레인)는 128개, 512비트(16레인)는 64개의 벡터 덧셈이 필요합니다. 스칼라는 1,024개입니다. 로드와 저장 명령은 계산에 넣지 않은 단순한 계산입니다.
작은 원소일수록 레인이 늘어납니다 — 1920 × 1080 크기의 8비트 한 채널 이미지는 픽셀이 2,073,600개입니다. 128비트 레지스터에 8비트 값이 16개 들어가므로 2,073,600 ÷ 16 = 129,600번의 벡터 연산으로 한 번 훑을 수 있습니다.
나머지가 생기는 경우 — 원소 10개를 4레인으로 처리하면 벡터 연산이 2번(원소 8개)이고, 남은 2개는 스칼라로 처리하면 2번이라 연산이 모두 4번입니다. 원소를 하나씩 처리하면 10번입니다.

자주 하는 오해

SIMD는 멀티스레딩과 같다 — SIMD는 한 코어의 명령 하나가 여러 데이터를 다루는 방식이고, 멀티스레딩은 코어(또는 스레드)마다 따로 명령을 실행하는 방식입니다. 둘은 겹치지 않으며 함께 쓸 수 있습니다.
레인 수만큼 항상 빨라진다 — 벡터화는 명령 수를 줄이지만 메모리에서 옮겨야 하는 데이터의 양은 그대로입니다. 그래서 메모리 대역폭이 병목인 작업은 레인 수만큼 빨라지지 않는 경우가 많고, 나머지 처리와 정렬되지 않은 데이터도 이득을 깎습니다.
컴파일러가 모든 루프를 알아서 벡터화한다 — 컴파일러는 루프 간 의존성, 포인터 별칭, 복잡한 분기를 만나면 벡터화하지 못할 수 있습니다. 어떤 루프가 벡터화됐는지는 컴파일러가 주는 보고 옵션으로 확인합니다.
SIMD는 GPU에만 있는 개념이다 — 일반 CPU에도 벡터 확장 명령이 있습니다. NVIDIA GPU는 스레드 32개 묶음(워프)이 한 번에 같은 명령을 실행하는 SIMT를 씁니다. SIMD와 비슷하지만 스레드마다 분기할 수 있고, 갈라지면 효율이 떨어집니다.

면접에서 이렇게 물어요

면접 질문

SIMD는 무엇이고 왜 빠른가요?

명령어 하나가 벡터 레지스터의 여러 레인에 같은 연산을 동시에 적용합니다. 같은 일을 하는 데 필요한 명령 수가 레인 수만큼 줄어서, 규칙적인 배열 연산에서 처리량이 늘어납니다.

면접 질문

벡터화하기 어려운 루프는 어떤 모양인가요?

앞 반복의 결과를 뒤 반복이 읽는 루프 간 의존성, 원소마다 분기가 크게 갈리는 코드, 연속되지 않은 주소를 읽는 접근이 대표적입니다. 의존성이 없다는 것을 컴파일러가 증명하지 못해도 벡터화되지 않습니다.

면접 질문

SIMD와 멀티스레딩은 어떻게 다른가요?

SIMD는 한 코어 안에서 명령 하나가 여러 데이터를 처리하는 데이터 병렬성이고, 멀티스레딩은 코어마다 독립적인 명령 흐름을 실행하는 병렬성입니다. 한 스레드 안에서 SIMD를 쓰고 스레드를 여러 개 두어 함께 쓸 수 있습니다.

면접 질문

배열 길이가 레인 수의 배수가 아니면 어떻게 하나요?

레인을 가득 채우는 반복을 먼저 돌리고, 남은 원소는 스칼라 반복으로 따로 처리하는 방법이 흔합니다. 마스크를 지원하는 명령어 집합에서는 남은 레인만 켜서 한 번에 처리할 수도 있습니다.

실제 시스템에서는

컴파일러의 자동 벡터화 — GCC 문서에 따르면 -ftree-vectorize는 루프 벡터화와 SLP 벡터화를 켭니다. 이 옵션은 -O3에서 켜지고, GCC 12부터는 -O2에서도 제한된 비용 모델(very-cheap)로 켜집니다. -fopt-info-vec 옵션으로 벡터화된 루프를 보고받을 수 있습니다.
NumPy — NumPy 문서는 일부 연산이 SIMD 명령으로 가속되며, 실행 중인 CPU가 지원하는 명령어 집합을 확인해 알맞은 구현을 고르는 구조를 설명합니다.
자바 Vector API — OpenJDK의 JEP 448은 지원하는 CPU에서 최적의 벡터 명령으로 컴파일되도록 설계된 Vector API(jdk.incubator.vector)를 인큐베이터 모듈로 소개합니다.
메모리와의 관계 — 벡터 연산이 넓어질수록 데이터를 얼마나 빨리 공급하느냐가 중요해집니다. 캐시 메모리 토픽에서 데이터가 가까이 있을 때와 아닐 때의 차이를 봅니다.
