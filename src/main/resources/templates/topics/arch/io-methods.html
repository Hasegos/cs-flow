I/O 방식

태그

I/O 방식은 CPU가 입출력 장치와 데이터를 주고받는 방법입니다. Programmed I/O → Interrupt-Driven → DMA 순으로 발전하며 CPU 효율이 점진적으로 개선됩니다.

핵심 개념

Programmed I/O

CPU가 장치 상태 레지스터를 반복 확인(Polling)하며 완료를 기다립니다. 구현이 단순하지만 I/O 내내 CPU가 점유되어 다른 작업을 할 수 없습니다.

핵심 개념

Interrupt-Driven I/O

CPU가 I/O 명령만 내리고 즉시 다른 작업으로 돌아갑니다. 장치가 완료되면 인터럽트 신호를 보내 CPU에 통보합니다. 폴링 낭비가 없어집니다.

핵심 개념

DMA (Direct Memory Access)

DMA 컨트롤러가 버스를 직접 제어해 장치↔메모리 간 데이터를 전송합니다. CPU는 시작과 완료 인터럽트 처리만 담당해 부담이 최소화됩니다.

핵심 개념

Interrupt Controller

여러 장치의 인터럽트 요청(IRQ)을 수집해 우선순위를 결정하고 CPU에 전달하는 하드웨어입니다. x86에서는 PIC, 현재는 APIC를 사용합니다.

핵심 개념

Device Controller

실제 I/O 장치(디스크, 키보드 등)와 시스템 버스 사이에서 신호를 변환하는 하드웨어입니다. 데이터 레지스터·상태 레지스터·커맨드 레지스터를 가집니다.

핵심 개념

사이클 스틸링

DMA가 버스를 점유하는 순간 CPU의 메모리 접근이 한 사이클 지연됩니다. 대용량 전송에서 CPU 효율 이득이 지연 비용보다 훨씬 크므로 실용적입니다.

방식별 CPU 점유율 — Programmed I/O: 전송 내내 100% / Interrupt-Driven: 명령+ISR 처리만 / DMA: 설정+ISR 처리만 (~0%)
ISR (Interrupt Service Routine) — 인터럽트 발생 시 실행되는 OS 핸들러입니다. 현재 실행 중인 프로세스를 잠시 중단하고 빠르게 처리 후 복귀합니다.
메모리 맵드 I/O — 장치 레지스터를 메모리 주소 공간에 매핑해 일반 메모리 명령(MOV)으로 I/O를 수행합니다. 포트 맵드 I/O(IN/OUT 명령)와 대비됩니다.
적용 사례 — 저속 소형 장치(GPIO, 센서): Programmed I/O 또는 IRQ / 고속 대용량 전송(NVMe, 네트워크 NIC): DMA / 현대 OS는 대부분 DMA 기반입니다.
버스 중재 (Bus Arbitration) — CPU와 DMA가 동시에 버스를 요청할 때 DMA 컨트롤러가 버스 사용 권한을 중재합니다. DMA 완료 후 CPU에 버스가 반환됩니다.
