인터럽트

태그

인터럽트(Interrupt)는 CPU가 현재 작업을 수행하는 도중 긴급한 이벤트가 발생했음을 알리는 신호입니다. CPU는 하던 일을 잠시 중단하고 해당 이벤트를 처리한 뒤, 원래 작업으로 돌아옵니다. 운영체제와 하드웨어 간 효율적인 소통의 핵심 메커니즘입니다.

핵심 개념

하드웨어 인터럽트

키보드 입력, 마우스 클릭, 네트워크 패킷 수신 등 외부 하드웨어 장치가 CPU에 보내는 신호입니다. 비동기적으로 발생하며 CPU는 이를 즉시 처리합니다.

핵심 개념

소프트웨어 인터럽트 (트랩)

프로그램이 의도적으로 발생시키는 인터럽트입니다. 시스템 콜(System Call)이 대표적이며, 사용자 모드에서 커널 기능을 요청할 때 사용됩니다.

핵심 개념

예외 (Exception)

0으로 나누기, 페이지 폴트, 잘못된 메모리 접근 등 CPU 내부에서 발생하는 오류 상황입니다. 동기적으로 발생하며 즉시 처리가 필요합니다.

핵심 개념

인터럽트 서비스 루틴 (ISR)

인터럽트 발생 시 실행되는 처리 함수입니다. 인터럽트 벡터 테이블(IVT)에 각 인터럽트 번호별 ISR 주소가 등록되어 있습니다.

핵심 개념

인터럽트 벡터 테이블 (IVT)

인터럽트 번호와 ISR 주소를 매핑한 테이블입니다. CPU는 인터럽트 발생 시 이 테이블을 참조해 해당 ISR의 주소를 찾아 점프합니다.

핵심 개념

인터럽트 우선순위

여러 인터럽트가 동시에 발생하면 우선순위가 높은 것을 먼저 처리합니다. 우선순위가 낮은 ISR 실행 중 높은 우선순위 인터럽트가 오면 중단하고 처리합니다.

컨텍스트 저장 — 인터럽트 발생 시 CPU는 현재 PC(프로그램 카운터), 레지스터 값 등을 스택에 저장합니다. ISR 종료 후 이를 복원해 원래 작업을 재개합니다.
인터럽트 마스킹 — ISR 실행 중 다른 인터럽트를 무시(마스킹)할 수 있습니다. 중요한 처리 중 재진입을 방지해 데이터 일관성을 보장합니다.
폴링 vs 인터럽트 — 폴링은 CPU가 주기적으로 장치 상태를 확인하는 방식으로 CPU 자원을 낭비합니다. 인터럽트 방식은 이벤트 발생 시에만 처리하므로 훨씬 효율적입니다.
인터럽트 컨트롤러 (PIC/APIC) — 여러 하드웨어 장치로부터 인터럽트 신호를 받아 우선순위를 조정하고 CPU에 전달하는 하드웨어 컴포넌트입니다.
RETI 명령어 — ISR의 마지막에 실행되는 인터럽트 복귀 명령어입니다. 스택에서 PC와 레지스터를 복원하고 인터럽트 플래그를 원상복구합니다.
