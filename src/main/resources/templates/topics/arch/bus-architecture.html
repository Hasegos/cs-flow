버스 구조

태그

버스(Bus)는 CPU, 메모리, I/O 장치가 데이터를 주고받는 공유 통신 경로입니다. 하나의 버스를 여러 장치가 공유하기 때문에 누가, 언제 버스를 사용할지 조율하는 중재(Arbitration) 메커니즘이 핵심입니다.

핵심 개념

Address Bus

CPU가 접근할 메모리 주소나 I/O 포트를 전달합니다. CPU에서 메모리·I/O 방향의 단방향 버스입니다. 주소선의 수가 주소 공간의 크기를 결정합니다.

핵심 개념

Data Bus

실제 데이터를 주고받는 통로입니다. CPU↔메모리, CPU↔I/O 모두 이 버스를 사용합니다. 양방향이며 버스 폭(8/16/32/64비트)이 한 번에 전송 가능한 데이터 크기를 결정합니다.

핵심 개념

Control Bus

Read/Write 신호, 인터럽트 요청(IRQ), 버스 요청(BR)/승인(BG) 등 제어 신호를 전달합니다. 양방향이며 버스 동작 전체를 지휘합니다.

핵심 개념

버스 중재 (Arbitration)

여러 장치가 동시에 버스를 요청할 때 우선순위를 결정합니다. 중앙집중식(Centralized)과 분산식(Distributed) 방식이 있으며, 현대 시스템은 대부분 중앙 Arbiter를 사용합니다.

핵심 개념

Bus Master / Slave

버스 사용권을 주도적으로 요청하는 Master(CPU, DMA)와 요청을 받아 응답하는 Slave(메모리, I/O)로 역할이 나뉩니다.

핵심 개념

DMA (Direct Memory Access)

I/O 장치가 CPU를 거치지 않고 메모리에 직접 접근하는 방식입니다. CPU 개입 없이 데이터 전송이 가능해 성능이 크게 향상됩니다.

버스 대역폭 (Bandwidth) — 버스 폭(비트 수) × 클록 주파수 × 클럭당 전송 횟수로 결정됩니다. SDR(Single Data Rate)은 × 1, DDR(Double Data Rate)은 클럭 상승·하강 엣지 양쪽에서 전송해 × 2가 됩니다. 현대 메모리(DDR4/DDR5)는 모두 DDR 방식입니다. 병목이 되면 CPU가 아무리 빨라도 전체 성능이 제한됩니다.
동기식 vs 비동기식 버스 — 동기식은 공통 클록에 맞춰 동작해 단순하지만 느린 장치에 발목이 잡힙니다. 비동기식은 핸드셰이킹으로 각 장치 속도에 맞춥니다.
단일 버스 vs 다중 버스 — 단일 버스는 구조가 단순하지만 동시 전송이 불가합니다. 현대 시스템은 고속(CPU-메모리)과 저속(I/O) 버스를 분리해 병목을 줄입니다.
데이지 체인 중재 — Bus Grant 신호를 장치 체인으로 순서대로 전달합니다. 구조는 단순하지만 앞 장치가 우선순위를 독점할 수 있습니다.
PCIe / USB — 현대 시스템은 병렬 공유 버스 대신 직렬 Point-to-Point 연결(PCIe, USB, SATA)을 사용해 대역폭과 안정성을 모두 확보합니다.
