인터럽트

태그

인터럽트(Interrupt)는 CPU가 현재 작업을 수행하는 도중 긴급한 이벤트가 발생했음을 알리는 신호입니다. CPU는 하던 일을 잠시 중단하고 해당 이벤트를 처리한 뒤, 원래 작업으로 돌아옵니다. 운영체제와 하드웨어 간 효율적인 소통의 핵심 메커니즘입니다.

핵심 개념

하드웨어 인터럽트

키보드 입력, 마우스 클릭, 네트워크 패킷 수신 등 외부 하드웨어 장치가 CPU에 보내는 신호입니다. 비동기적으로 발생하며 CPU는 현재 명령어를 끝낸 뒤 처리합니다.

핵심 개념

소프트웨어 인터럽트 (트랩)

프로그램이 의도적으로 발생시키는 인터럽트입니다. 시스템 콜(System Call)이 대표적이며, 사용자 모드에서 커널 기능을 요청할 때 사용됩니다.

핵심 개념

예외 (Exception)

0으로 나누기, 페이지 폴트, 잘못된 메모리 접근 등 CPU 내부에서 발생하는 오류 상황입니다. 동기적으로 발생하며 즉시 처리가 필요합니다.

핵심 개념

인터럽트 서비스 루틴 (ISR)

인터럽트 발생 시 실행되는 처리 함수입니다. x86 실제 모드에서는 IVT(Interrupt Vector Table), 보호 모드(현대 OS)에서는 IDT(Interrupt Descriptor Table)에 각 인터럽트 번호별 ISR 주소가 등록되어 있습니다.

핵심 개념

인터럽트 디스크립터 테이블 (IDT / IVT)

인터럽트 번호와 ISR 주소를 매핑한 테이블입니다. x86 실제 모드에서는 IVT를, 보호 모드(현대 OS)에서는 IDT를 사용합니다. CPU는 인터럽트 발생 시 이 테이블을 참조해 해당 ISR로 점프합니다.

핵심 개념

인터럽트 우선순위

여러 인터럽트가 동시에 발생하면 우선순위가 높은 것을 먼저 처리합니다. 중첩을 허용하는 구성에서는 우선순위가 낮은 ISR 실행 중 높은 우선순위 인터럽트가 오면 중단하고 처리합니다.

컨텍스트 저장 — 인터럽트 발생 시 CPU는 복귀에 필요한 최소한의 상태(32비트 x86은 EIP, CS, EFLAGS 등)를 스택에 저장하고, 나머지 레지스터는 ISR이 필요하면 직접 저장합니다. ISR 종료 후 이를 복원해 원래 작업을 재개합니다.
인터럽트 마스킹 — ISR 실행 중 다른 인터럽트를 무시(마스킹)할 수 있습니다. 중요한 처리 중 재진입을 방지해 데이터 일관성을 보장합니다.
폴링 vs 인터럽트 — 폴링은 CPU가 주기적으로 장치 상태를 확인하는 방식으로 CPU 자원을 낭비합니다. 인터럽트 방식은 이벤트 발생 시에만 처리하므로 대개 더 효율적입니다(이벤트가 아주 잦으면 예외).
인터럽트 컨트롤러 (PIC/APIC) — 여러 하드웨어 장치로부터 인터럽트 신호를 받아 우선순위를 조정하고 CPU에 전달하는 하드웨어 컴포넌트입니다.
IRET 명령어 — ISR의 마지막에 실행되는 x86 인터럽트 복귀 명령어입니다. 스택에서 EIP, CS, EFLAGS를 복원하며, IF는 복원된 EFLAGS 값에 따라 정해집니다. (다른 아키텍처에는 각자의 복귀 명령이 있습니다.)

인터럽트의 종류와 번호

x86에서 인터럽트와 예외는 0~255번 벡터 번호로 구분됩니다. 인텔 설명서에서 0~31번은 아키텍처가 정의한 예외와 인터럽트용으로 예약되어 있고, 32~255번은 운영체제와 장치가 쓸 수 있는 번호입니다. 예를 들어 0번은 0으로 나누기 오류(#DE), 14번은 페이지 폴트(#PF)입니다. 마스크로 막을 수 없는 NMI(Non-Maskable Interrupt)도 따로 있습니다.

숫자로 확인하기

IVT 크기 — x86 실제 모드의 인터럽트 벡터 테이블은 256개 항목에 항목당 4바이트(오프셋과 세그먼트 각 2바이트)여서 1KB입니다.
IDT 크기 — 보호 모드의 인터럽트 디스크립터 테이블은 최대 256개 항목이고 항목은 8바이트라 최대 2KB입니다. 64비트 모드에서는 항목이 16바이트라 최대 4KB입니다.
폴링의 낭비를 숫자로 — 설명용 값으로, 1ms마다 장치 상태를 확인하는데 이벤트가 하루에 한 번만 온다면 하루에 8,640만 번 확인하고 8,639만 9,999번은 헛걸음입니다. 인터럽트는 이벤트가 올 때 한 번만 CPU를 부릅니다.

자주 하는 오해

인터럽트와 예외는 같은 것이다 — 하드웨어 인터럽트는 CPU 바깥 장치가 비동기로 일으키고, 예외는 실행 중인 명령어 때문에 CPU 안에서 동기로 일어납니다. 둘 다 같은 벡터 테이블을 거쳐 처리되어서 비슷해 보일 뿐입니다.
인터럽트가 오면 곧바로 다른 프로세스로 바뀐다 — ISR이 끝나면 대개 원래 실행하던 곳으로 돌아갑니다. 프로세스 전환은 ISR 안에서 스케줄러가 필요하다고 판단한 경우에 일어납니다.
ISR은 시간이 오래 걸려도 된다 — ISR이 길면 그동안 다른 인터럽트의 처리가 늦어질 수 있습니다. 그래서 인터럽트 처리는 급한 부분만 ISR에서 하고 나머지는 나중으로 미루는 구조가 흔합니다. 교재와 리눅스 자료에서는 이 나중 처리를 bottom half라고 부르고, softirq, tasklet, workqueue 같은 수단을 씁니다.
인터럽트 방식이 항상 폴링보다 낫다 — 이벤트가 아주 자주 오면 인터럽트 처리 비용이 쌓입니다. 리눅스 네트워크 드라이버가 부하가 높을 때 인터럽트 대신 폴링으로 바꾸는 NAPI가 그 예입니다.

면접에서 이렇게 물어요

면접 질문

인터럽트, 예외, 트랩은 어떻게 다른가요?

인터럽트는 외부 장치가 비동기로 보내는 신호이고, 예외는 명령어 실행 중 CPU가 감지한 오류 상황으로 동기로 발생합니다. 트랩은 프로그램이 의도적으로 일으키는 소프트웨어 인터럽트로 시스템 콜이 대표적입니다. 책마다 용어를 묶는 방식이 조금씩 다릅니다.

면접 질문

인터럽트가 발생하면 CPU는 무엇을 하나요?

현재 명령어를 끝낸 뒤 복귀에 필요한 상태(32비트 보호 모드에서는 EIP, CS, EFLAGS이고, 권한 수준이 바뀌면 SS:ESP도, 일부 예외는 에러 코드도)를 스택에 저장하고, 벡터 번호로 IDT를 찾아 ISR로 점프합니다. ISR이 끝나면 IRET으로 저장한 상태를 복원해 원래 흐름으로 돌아갑니다.

면접 질문

ISR 안에서 다른 인터럽트가 오면 어떻게 되나요?

x86에서 인터럽트 게이트로 진입하면 CPU가 인터럽트 플래그(IF)를 꺼서 마스커블 인터럽트를 막습니다. ISR이 IF를 다시 켜면 더 높은 우선순위의 인터럽트를 받는 중첩이 가능합니다. 방식은 구조와 운영체제마다 다릅니다.

면접 질문

폴링과 인터럽트는 언제 무엇을 쓰나요?

이벤트가 드물고 언제 올지 모르면 인터럽트가 CPU 시간을 아낍니다. 이벤트가 매우 자주 오거나 응답 지연을 극단적으로 줄여야 하면 폴링이 나을 수 있습니다.

실제 시스템에서는

리눅스 인터럽트 통계 — cat /proc/interrupts를 실행하면 인터럽트 번호별로 CPU마다 처리한 횟수를 볼 수 있습니다. 키보드를 누르거나 네트워크로 패킷을 받을 때 해당 줄의 숫자가 늘어나는 것을 확인할 수 있습니다.
타이머 인터럽트와 스케줄링 — 운영체제는 주기적인 타이머 인터럽트를 받아 실행 중인 프로세스에게서 CPU를 회수할 기회를 얻습니다. 선점형 스케줄링은 이 인터럽트에 의존합니다.
네트워크 드라이버의 NAPI — 리눅스 커널 문서에 따르면 NAPI는 패킷이 많이 들어올 때 인터럽트를 줄이고 폴링으로 처리하는 방식입니다.
