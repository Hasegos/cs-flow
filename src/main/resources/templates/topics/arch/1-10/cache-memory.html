캐시 메모리

태그

캐시 메모리(Cache Memory)는 CPU와 주기억장치(RAM) 사이에 위치한 초고속 임시 저장 공간입니다. CPU가 자주 쓰는 데이터를 미리 담아두어 메모리 접근 속도 차이를 극복하고 전체 성능을 끌어올립니다.

핵심 개념

캐시 히트 (Cache Hit)

CPU가 요청한 데이터가 캐시에 있는 경우입니다. 메인 메모리 접근 없이 캐시에서 바로 데이터를 가져오므로 매우 빠릅니다.

핵심 개념

캐시 미스 (Cache Miss)

CPU가 요청한 데이터가 캐시에 없는 경우입니다. 메인 메모리에서 데이터를 가져온 뒤 캐시에 적재(Load)합니다.

핵심 개념

지역성 원리

시간 지역성(방금 쓴 데이터를 곧 다시 씀)과 공간 지역성(인접한 주소의 데이터를 곧 씀)을 활용해 캐시 효율을 높입니다.

핵심 개념

캐시 계층 (L1 / L2 / L3)

L1은 가장 빠르고 작으며 CPU 코어에 직접 붙어있습니다. L2·L3로 갈수록 느리지만 용량이 커집니다.

핵심 개념

교체 정책 (LRU)

캐시 라인을 넣을 자리(세트)가 가득 찼을 때 가장 오랫동안 사용되지 않은 라인을 제거합니다. LRU(Least Recently Used)가 대표적이며, 실제 CPU는 비용을 줄이려고 LRU를 근사한 방식(pseudo-LRU)을 쓰기도 합니다.

핵심 개념

쓰기 정책

Write-Through는 캐시와 메모리를 동시에 갱신합니다. Write-Back은 캐시만 먼저 갱신하고 나중에 메모리에 반영합니다.

히트율 (Hit Rate) — 전체 메모리 접근 중 캐시 히트 비율입니다. 히트율이 높을수록 성능이 좋습니다. 실제 값은 프로그램의 접근 패턴과 캐시 구성에 따라 크게 달라집니다.
블록 (Block / Cache Line) — 캐시는 데이터를 바이트 단위가 아닌 블록(보통 64바이트) 단위로 메모리에서 가져옵니다. 공간 지역성 활용의 핵심입니다.
직접 매핑 (Direct Mapped) — 메모리 블록이 캐시의 고정된 한 슬롯에만 들어갈 수 있습니다. 구조가 단순하지만 충돌 미스가 발생할 수 있습니다.
연관 매핑 (Fully Associative) — 메모리 블록이 캐시의 어느 슬롯에든 들어갈 수 있습니다. 충돌 미스가 없지만 검색 비용이 높습니다.
세트 연관 매핑 (Set Associative) — 직접·연관 매핑의 절충안입니다. 캐시를 세트로 나누고 각 세트 내에서 연관 매핑을 적용합니다.

캐시가 나온 배경

1965년 모리스 윌크스(Maurice Wilkes)가 '슬레이브 메모리(slave memory)'라는 이름으로 큰 주기억장치 앞에 작고 빠른 메모리를 두는 개념을 제안했고, 상용 컴퓨터에 캐시를 넣은 초기 사례로는 1960년대 후반의 IBM System/360 모델 85가 알려져 있습니다. 오늘날 CPU와 메모리의 속도 차이가 커서, 캐시가 없으면 메모리 접근 대기가 성능을 크게 좌우합니다. 캐시는 SRAM으로 만들고 주기억장치는 보통 DRAM으로 만듭니다.

캐시는 주소를 이렇게 나눠 봅니다

캐시는 메모리 주소를 태그(tag) · 인덱스(index) · 오프셋(offset) 세 부분으로 나눠 해석합니다. 오프셋은 캐시 라인 안의 위치, 인덱스는 어느 세트에 있는지, 태그는 그 자리에 있는 라인이 찾는 주소의 것이 맞는지 확인하는 값입니다. 예를 들어 32KB, 8-way, 라인 64바이트 캐시(예: Intel Skylake, AMD Zen 4의 L1 데이터 캐시 구성)는 세트가 32768 ÷ (64 × 8) = 64개이므로 오프셋 6비트, 인덱스 6비트를 쓰고 나머지 상위 비트가 태그입니다.

캐시 미스의 세 가지 종류

강제 미스(Compulsory) — 그 블록을 처음 접근해서 캐시에 없는 경우입니다. 캐시가 아무리 커도 피할 수 없습니다.
용량 미스(Capacity) — 작업에 필요한 데이터가 캐시보다 커서 쫓겨났다가 다시 필요해지는 경우입니다. 캐시를 키우면 줄어듭니다.
충돌 미스(Conflict) — 캐시에 빈 곳이 있어도 직접 매핑이나 세트 연관 매핑에서 같은 세트로 몰려 쫓겨나는 경우입니다. 연관도(way 수)를 높이면 줄어듭니다.

자주 하는 오해

캐시는 읽기만 빠르게 해 준다 — 쓰기도 캐시를 거칩니다. Write-Back 방식은 캐시 라인에 더티(dirty) 비트를 두고, 그 라인이 쫓겨날 때에만 메모리에 써서 메모리 쓰기 횟수를 줄입니다.
멀티코어에서는 캐시를 코어가 함께 쓰니 동기화 걱정이 없다 — L1은 코어마다 있어서 같은 주소를 서로 다른 값으로 갖지 않도록 캐시 일관성 프로토콜(MESI 등)이 필요합니다. 또 서로 다른 변수라도 같은 캐시 라인에 있으면 한 코어의 쓰기가 다른 코어의 캐시 라인을 무효화하는 거짓 공유(false sharing)로 느려질 수 있습니다.
히트율이 90%면 충분하다 — 미스 한 번의 비용이 히트보다 훨씬 커서 히트율이 몇 %p만 달라져도 평균 접근 시간이 크게 달라집니다. 메모리 계층 구조 토픽의 계산 예를 보세요.
캐시는 코드와 무관한 하드웨어의 일이다 — 캐시는 하드웨어가 자동으로 관리하지만, 같은 데이터를 어떤 순서로 접근하는지에 따라 히트율이 크게 달라집니다.

면접에서 이렇게 물어요

면접 질문

직접 매핑, 연관 매핑, 세트 연관 매핑을 비교해 보세요.

직접 매핑은 블록이 들어갈 자리가 하나라 검색이 빠르고 구조가 단순하지만 충돌 미스가 많습니다. 완전 연관은 어디든 들어가 충돌 미스가 없지만 모든 라인의 태그를 비교해야 해서 비용이 큽니다. 세트 연관은 이 둘의 절충으로, 실제 CPU 캐시는 대부분 세트 연관 구조입니다.

면접 질문

Write-Through와 Write-Back의 차이는 무엇인가요?

Write-Through는 쓸 때마다 캐시와 메모리를 함께 갱신해 단순하고 메모리가 항상 최신이지만 쓰기가 느려지기 쉽습니다(쓰기 버퍼로 완화하기도 합니다). Write-Back은 캐시만 갱신하고 라인이 교체될 때 메모리에 반영해 빠르지만, 더티 비트 관리와 멀티코어 일관성 처리가 필요합니다.

면접 질문

거짓 공유(false sharing)란 무엇이고 어떻게 피하나요?

서로 다른 스레드가 쓰는 서로 다른 변수가 같은 캐시 라인에 있어서, 한쪽이 쓸 때마다 다른 쪽 코어의 그 라인이 무효화되어 성능이 떨어지는 현상입니다. 자주 쓰는 변수를 라인 단위로 띄워 배치(패딩)해서 피합니다.

면접 질문

공간 지역성을 살리려면 코드를 어떻게 짜야 하나요?

연속된 주소를 순서대로 접근하게 합니다. 2차원 배열은 C처럼 행 우선으로 저장하는 언어에서는 행 단위로 순회하고, 자주 같이 쓰는 필드는 같은 구조체나 객체에 모아 한 캐시 라인에 들어가게 합니다.

실제 시스템에서는

lscpu — CPU의 L1d, L1i, L2, L3 캐시 크기를 보여줍니다(man 문서에 따르면 전체 CPU를 요약한 값입니다).
리눅스 perf stat — -e cache-references,cache-misses 이벤트로 캐시 참조와 미스 횟수를 세어 미스율을 계산할 수 있습니다. 보통 마지막 레벨 캐시(LLC) 기준이며, 이벤트의 정확한 의미는 CPU마다 다릅니다.
Java의 LongAdder — 값을 여러 셀에 나눠 더하고 필요할 때 합치는 구조로, 서로 다른 셀이 같은 캐시 라인에 놓여 거짓 공유가 생기지 않도록 셀에 패딩 어노테이션(@Contended)을 붙입니다.
