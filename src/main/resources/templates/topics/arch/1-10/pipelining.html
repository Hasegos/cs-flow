파이프라이닝

태그

파이프라이닝(Pipelining)은 명령어 실행을 여러 단계로 나눠 각 단계를 동시에 겹쳐서 처리하는 기법입니다. 공장 조립 라인처럼, 한 명령어가 다음 단계로 넘어가는 동시에 다음 명령어가 그 자리를 채웁니다.

1단계

IF — Instruction Fetch

PC가 가리키는 메모리 주소에서 명령어를 읽어옵니다. 읽은 후 PC는 자동으로 다음 주소로 증가합니다.

2단계

ID — Instruction Decode

IF/ID 레지스터에 담긴 명령어를 해석합니다. 필요한 레지스터를 읽고 제어 신호를 생성합니다.

3단계

EX — Execute

ALU가 실제 연산을 수행합니다. 산술·논리 연산 또는 메모리 접근을 위한 주소를 계산합니다.

4단계

MEM — Memory Access

필요한 경우 메모리에서 데이터를 읽거나 씁니다. LOAD/STORE 명령어에서 실제 메모리 접근이 일어납니다.

5단계

WB — Write Back

결과를 써야 하는 명령어는 목적지 레지스터에 저장합니다. 파이프라인의 마지막 단계로 명령어 실행이 완료됩니다.

핵심 개념

파이프라인 해저드

데이터 의존성(Data Hazard), 제어 해저드(Control Hazard), 구조적 해저드(Structural Hazard)로 인해 파이프라인이 멈출 수 있습니다.

성능 향상 — 파이프라이닝 없이 5단계 명령어 4개를 처리하면 20클럭이 필요하지만, 파이프라이닝 적용 시 이상적으로 8클럭으로 단축됩니다.
처리량 vs 지연시간 — 파이프라이닝은 개별 명령어의 실행 시간(지연시간)을 줄이지 않습니다. 단위 시간당 완료되는 명령어 수(처리량)를 높입니다.
파이프라인 스톨(Stall) — 해저드가 생기면 CPU는 버블(Bubble)을 삽입해 대기합니다. 이렇게 파이프라인이 멈추는 현상을 스톨이라 하고, 해저드를 감지해 파이프라인을 멈추게 하는 하드웨어를 인터록(Interlock)이라 합니다.
포워딩(Forwarding) — 데이터 해저드를 줄이기 위해 아직 WB 단계를 거치지 않은 연산 결과를 다음 명령어의 EX 단계에 직접 전달하는 기법입니다.
분기 예측(Branch Prediction) — 제어 해저드를 줄이기 위해 분기 결과를 미리 예측하고 실행합니다. 예측이 틀리면 파이프라인을 플러시(Flush)합니다.

속도 향상은 어떻게 계산되나요

단계가 k개인 파이프라인에서 명령어 N개를 처리하면 첫 명령어가 끝나는 데 k사이클이 걸리고 이후에는 매 사이클 하나씩 끝나므로, 총 N + k − 1 사이클이 듭니다. 파이프라인이 없으면 N × k 사이클입니다. 5단계에서 명령어 100개를 처리하면 104사이클과 500사이클이라 약 4.8배 빨라지고, N이 커질수록 단계 수 5에 가까워집니다. 이 값은 모든 단계의 시간이 같고 해저드가 없을 때의 이상적인 값입니다. 실제 클럭 주기는 가장 느린 단계의 시간에 단계 사이 레지스터의 지연을 더한 값으로 정해집니다.

해저드 세 가지를 조금 더 자세히

구조적 해저드 — 두 명령어가 같은 하드웨어를 같은 사이클에 쓰려 할 때 생깁니다. 메모리가 하나이면 IF 단계의 명령어 읽기와 MEM 단계의 데이터 접근이 겹치므로, 명령어 캐시와 데이터 캐시를 나누는 식으로 해결합니다.
데이터 해저드 — 앞 명령어의 결과가 아직 레지스터에 쓰이지 않았는데 뒤 명령어가 그 값을 읽으려 할 때 생깁니다. 포워딩으로 대부분 해결하지만, LOAD 바로 다음 명령어가 그 값을 쓰는 경우(load-use)는 5단계 파이프라인에서 포워딩을 해도 1사이클을 기다려야 합니다.
제어 해저드 — 분기 결과가 정해지기 전에는 다음에 가져올 명령어를 알 수 없을 때 생깁니다. 기다리거나(스톨), 예측하거나(분기 예측), 분기 뒤의 명령어를 먼저 실행하는 분기 지연 슬롯으로 줄입니다.

자주 하는 오해

단계가 많을수록 무조건 빠르다 — 단계를 잘게 나누면 클럭을 높일 수 있지만, 분기 예측이 틀렸을 때 버려지는 명령어와 단계 사이 레지스터의 오버헤드도 늘어납니다. 인텔 펜티엄 4(NetBurst)는 20단계까지 늘렸지만, 이후 Core 마이크로아키텍처는 단계 수를 줄였습니다.
파이프라이닝은 멀티코어와 같은 병렬 처리다 — 파이프라인은 코어 하나 안에서 서로 다른 명령어가 서로 다른 단계에 있는 것(명령어 수준 병렬성)이고, 멀티코어는 코어 여러 개가 각자 명령어를 실행하는 것입니다. 한 사이클에 명령어를 여러 개 시작하는 슈퍼스칼라는 파이프라인을 폭으로 넓힌 구조입니다.
파이프라인 스톨은 오류다 — 정확한 결과를 위해 하드웨어가 일부러 기다리는 정상 동작입니다. 틀리는 것이 아니라 느려지는 것입니다.
x86 같은 복잡한 명령어 집합은 파이프라인을 쓸 수 없다 — x86 CPU는 명령어를 내부에서 더 단순한 마이크로 연산으로 변환하고, 복잡한 명령어는 여러 개로 나누거나 마이크로코드로 처리해 파이프라인에 태웁니다. 그래서 겉모습은 복잡해도 내부는 파이프라인 구조를 따릅니다.

면접에서 이렇게 물어요

면접 질문

5단계 파이프라인에서 명령어 100개를 실행하면 몇 사이클이 걸리나요?

해저드가 없다고 하면 N + k − 1 = 100 + 5 − 1 = 104사이클입니다. 파이프라인이 없으면 100 × 5 = 500사이클이므로 약 4.8배 빠릅니다.

면접 질문

데이터 해저드는 어떻게 해결하나요?

세 가지입니다. 결과가 준비될 때까지 버블을 넣고 기다리는 스톨, 결과를 레지스터에 쓰기 전에 다음 명령어의 EX 단계로 바로 보내는 포워딩, 컴파일러가 의존성이 있는 명령어를 떨어뜨려 배치하는 명령어 스케줄링입니다.

면접 질문

RISC가 파이프라인에 유리한 이유는 무엇인가요?

명령어 길이가 일정하고 형식이 단순해 해석이 쉽고, 메모리 접근이 LOAD와 STORE로 한정되어 주소 계산(EX)과 메모리 접근(MEM)을 서로 다른 단계로 나눌 수 있습니다. 그래서 모든 명령어를 같은 5단계 순서에 넣기 쉽습니다.

면접 질문

제어 해저드를 줄이는 방법은 무엇인가요?

분기가 확정될 때까지 기다리는 스톨, 결과를 미리 맞혀 보는 분기 예측, 분기 바로 뒤의 명령어를 분기와 상관없이 실행하는 분기 지연 슬롯이 있습니다. 현대 CPU는 보통 분기 예측을 씁니다.

실제 시스템에서는

교재 속 5단계 모델 — IF, ID, EX, MEM, WB 5단계 파이프라인은 MIPS 같은 초기 RISC 프로세서를 바탕으로 한 컴퓨터 구조 교재의 표준 설명 모델입니다. 오늘날의 CPU는 이보다 훨씬 복잡합니다.
리눅스 perf stat — 실행한 명령어 수와 사이클 수, 사이클당 명령어 수(IPC)를 출력합니다. IPC가 평균 1보다 크면 한 사이클에 명령어를 둘 이상 끝낸다는 뜻이라 슈퍼스칼라 구조임을 알 수 있습니다.
