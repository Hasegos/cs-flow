시스템 콜

태그

시스템 콜은 사용자 프로그램이 OS 커널의 서비스를 요청하는 유일한 공식 통로입니다. 프로세스는 파일 읽기·네트워크·프로세스 생성 등 하드웨어 접근이 필요한 모든 작업에서 반드시 시스템 콜을 통해 커널에 요청합니다.

핵심 개념

유저 모드 / 커널 모드

CPU는 두 가지 특권 수준을 갖습니다. 유저 모드(Ring 3)는 제한된 명령만 실행하며 하드웨어에 직접 접근할 수 없습니다. 커널 모드(Ring 0)는 모든 명령과 하드웨어에 접근 가능합니다. 시스템 콜이 두 모드를 전환시킵니다.

핵심 개념

트랩 (Trap)

시스템 콜 호출 시 발생하는 소프트웨어 인터럽트입니다. x86에서는 int 0x80(구식) 또는 syscall 명령어를 사용합니다. 트랩이 발생하면 CPU가 커널 모드로 전환되고 미리 등록된 트랩 핸들러가 실행됩니다.

핵심 개념

시스템 콜 테이블

각 시스템 콜에는 고유 번호가 있습니다. Linux x86-64에서 read=0, write=1, open=2, close=3, fork=57, execve=59, exit=60입니다. 커널은 이 번호로 sys_call_table에서 핸들러 함수를 찾아 실행합니다.

핵심 개념

시스템 콜 종류

파일 제어(open·read·write·close), 프로세스 제어(fork·exec·exit·wait), 메모리 관리(mmap·brk), 장치 제어(ioctl), 정보 유지(getpid·time), 통신(socket·send·recv)의 6가지로 분류됩니다.

핵심 개념

C 라이브러리 래퍼

프로그래머는 보통 시스템 콜을 직접 호출하지 않습니다. glibc의 printf()→write(), fopen()→open() 같이 표준 라이브러리가 시스템 콜을 래핑합니다. 이를 통해 이식성이 보장되고 에러 처리가 표준화됩니다.

핵심 개념

시스템 콜 오버헤드

모드 전환에는 수백 나노초~수 마이크로초가 소요됩니다. 레지스터 저장·복원, TLB 플러시, 컨텍스트 전환 비용이 발생합니다. vDSO(virtual Dynamic Shared Object)는 gettimeofday() 같은 일부 시스템 콜을 모드 전환 없이 처리합니다.

syscall 명령어 (x86-64) — RAX에 시스템 콜 번호, RDI·RSI·RDX 등에 인수를 넣고 syscall을 실행합니다. 커널은 처리 후 RAX에 반환값을 저장하고 sysret으로 유저 모드로 복귀합니다.
strace 도구 — 프로세스의 모든 시스템 콜을 추적합니다. `strace ls` 실행 시 execve·openat·read·write 등 수십 개의 시스템 콜이 표시됩니다. 성능 분석과 디버깅에 유용합니다.
Spectre/Meltdown 이후 — CPU 취약점 패치(KPTI)로 시스템 콜마다 페이지 테이블을 교체하게 되어 성능이 크게 저하됐습니다. 최신 CPU는 하드웨어 수준에서 이를 완화합니다.
seccomp — 프로세스가 사용할 수 있는 시스템 콜을 필터링합니다. Docker·Chrome 샌드박스가 seccomp을 사용해 컨테이너/프로세스가 호출할 수 있는 시스템 콜을 제한합니다.
