가상 메모리

태그

가상 메모리는 실제 물리 메모리보다 더 큰 주소 공간을 프로세스에 제공하는 기법입니다. 필요한 페이지만 물리 메모리에 올리고(Demand Paging), 부족하면 교체 알고리즘으로 어떤 페이지를 내보낼지 결정합니다.

핵심 개념

요구 페이징 (Demand Paging)

프로세스 실행 시 모든 페이지를 메모리에 올리지 않고, 실제 접근할 때만 적재합니다. 페이지 폴트(Page Fault)가 발생하면 OS가 디스크에서 해당 페이지를 읽어옵니다.

핵심 개념

FIFO (First-In, First-Out)

가장 먼저 적재된 페이지를 교체합니다. 구현이 단순하지만 프레임 수를 늘려도 폴트가 증가하는 Belady's Anomaly가 발생할 수 있습니다.

핵심 개념

LRU (Least Recently Used)

가장 오랫동안 사용되지 않은 페이지를 교체합니다. 최근 사용 기록을 기반으로 미래를 예측합니다. 구현 비용이 높지만 실용적으로 좋은 성능을 보입니다.

핵심 개념

Optimal (OPT)

앞으로 가장 오랫동안 사용되지 않을 페이지를 교체합니다. 미래를 알아야 하므로 실제 구현 불가능하지만 다른 알고리즘 성능 비교의 기준(Upper Bound)이 됩니다.

핵심 개념

스래싱 (Thrashing)

프로세스가 페이지 교체에만 시간을 쏟아 실제 작업을 못하는 현상입니다. 물리 메모리 프레임 수가 프로세스의 워킹셋(Working Set)보다 작을 때 발생합니다.

핵심 개념

워킹셋 (Working Set)

특정 시간 윈도우 내에 프로세스가 참조한 페이지 집합입니다. 워킹셋 크기만큼 프레임이 확보되면 폴트율이 급격히 낮아집니다. 지역성(Locality) 원리를 기반으로 합니다.

Belady's Anomaly — FIFO에서 프레임 수를 늘렸는데 오히려 페이지 폴트가 증가하는 현상입니다. LRU·OPT는 이 현상이 없어 Stack Algorithm이라 불립니다.
Copy-on-Write (CoW) — fork() 시 부모·자식이 같은 물리 페이지를 공유하다가 쓰기 발생 시점에만 복사합니다. 불필요한 복사를 줄여 fork() 성능을 크게 향상시킵니다.
페이지 폴트 처리 순서 — ① 유효 비트 확인 → ② OS 트랩 → ③ 빈 프레임 확인 → ④ 교체 알고리즘 선택 → ⑤ 디스크 I/O → ⑥ 페이지 테이블 갱신 → ⑦ 프로세스 재개. 디스크 I/O가 포함되어 수 밀리초가 소요됩니다.
Clock 알고리즘 (Second Chance) — FIFO의 변형으로 참조 비트(R)를 추가합니다. 교체 대상이 R=1이면 R을 0으로 바꾸고 기회를 한 번 더 줍니다. LRU의 근사 구현으로 Linux에서 사용합니다.
