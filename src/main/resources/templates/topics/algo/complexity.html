시간/공간 복잡도

태그

시간/공간 복잡도(Big-O 표기법)는 입력 크기 n이 커질수록 실행 시간이나 메모리 사용량이 얼마나 빠르게 늘어나는지를 나타내는 표기법입니다. 정확한 초 단위가 아니라 "커지는 추세(패턴)"에 집중한다는 점이 핵심입니다.

핵심 개념

O(1) — 상수 시간

입력 크기와 상관없이 항상 일정한 횟수만 연산합니다. 예: 배열에서 인덱스로 값 하나를 바로 꺼내는 연산.

핵심 개념

O(log n) — 로그 시간

매 단계마다 처리할 범위를 절반씩 줄여나갈 때 나타납니다. 예: 다음 토픽에서 다룰 이진 탐색.

핵심 개념

O(n) — 선형 시간

입력 전체를 한 번씩은 훑어야 하는 경우입니다. 예: 배열을 처음부터 끝까지 순회하며 최댓값을 찾는 연산.

핵심 개념

O(n²) — 이차 시간

입력의 모든 쌍을 서로 비교해야 할 때 나타납니다. 예: 이중 for문, 버블 정렬(자료구조-09 자료구조에서 다룸).

핵심 개념

O(2ⁿ) — 지수 시간

매 단계마다 선택지가 두 배씩 늘어날 때 나타납니다. 예: 캐시 없이 재귀로 계산하는 피보나치(자료구조-10에서 다룬 완전 탐색).

핵심 개념

시간·공간 트레이드오프

복잡도는 실행 시간뿐 아니라 메모리 사용량도 같은 방식(O(1), O(n)...)으로 표현합니다. 메모이제이션은 시간을 아끼는 대신 공간을 더 쓰는 대표적인 예입니다.

왜 정확한 초 단위가 아니라 빅오인가 — 컴퓨터 성능이나 사용하는 언어에 따라 실제 걸리는 시간은 달라지지만, "n이 커질 때 얼마나 빠르게 증가하는가"라는 패턴은 알고리즘 고유의 성질이라 비교 기준으로 삼기 좋습니다.
최선 / 평균 / 최악의 경우 — 같은 알고리즘도 입력에 따라 다르게 동작할 수 있습니다(예: 이미 정렬된 배열에서는 버블 정렬도 훨씬 빠르게 끝납니다). 빅오는 보통 가장 나쁜 경우(최악)를 기준으로 표기해 안전하게 성능을 예측합니다.
실전에서의 의미 — n이 10 정도면 어떤 알고리즘을 써도 체감 차이가 없습니다. 하지만 n이 수백만 단위로 커지면 O(n²) 알고리즘은 멈춘 것처럼 느껴지고, O(n log n)이나 O(n)은 여전히 빠릅니다. 그래서 문제 규모에 맞는 알고리즘 선택이 중요합니다.
이 시각화에서 확인할 것 — "그래프로 보기"에서는 n이 커질 때 다섯 복잡도가 그리는 곡선의 모양 차이를, "숫자로 비교"에서는 n=10 / 100 / 1000일 때 실제 연산 횟수가 얼마나 벌어지는지를 직접 숫자로 확인합니다.
