DP 기초

태그

ds-10(동적 프로그래밍 기초)에서는 피보나치 하나로 완전탐색·메모이제이션·타뷸레이션을 비교했다면, 여기서는 0/1 배낭 문제(Knapsack)로 DP를 한 단계 확장합니다. 피보나치는 1차원 표였지만, 배낭 문제는 "아이템 개수"와 "배낭 용량"이라는 두 축을 가진 2차원 표를 채워야 합니다.

핵심 개념

0/1 배낭 문제란

무게와 가치가 정해진 아이템들이 있을 때, 정해진 무게 한도(배낭 용량) 안에서 가치의 합이 최대가 되도록 아이템을 고르는 문제입니다. 각 아이템은 "넣거나(1) 안 넣거나(0)"만 가능합니다.

핵심 개념

2차원 DP 테이블

dp[i][w]는 "처음 i개의 아이템만 고려했을 때, 용량 w로 얻을 수 있는 최대 가치"를 의미합니다. 행은 아이템 개수, 열은 용량을 나타냅니다.

핵심 개념

점화식: 포함 vs 제외

매 칸마다 "이 아이템을 포함했을 때"와 "포함하지 않았을 때" 중 더 큰 값을 선택합니다: dp[i][w] = max(dp[i-1][w], dp[i-1][w-무게]+가치) (w가 아이템 무게 이상일 때만 포함 경우를 따집니다).

핵심 개념

기저 사례

아이템이 0개(0행)이거나 용량이 0(0열)이면 담을 수 있는 가치도 항상 0입니다. 이 두 경계가 모든 계산의 출발점입니다.

핵심 개념

값만으론 부족하다 — 역추적

테이블의 오른쪽 아래 칸은 "최댓값"만 알려줄 뿐, "어떤 아이템을 골랐는지"는 알려주지 않습니다. 어떤 아이템이 선택됐는지 알려면 표를 거슬러 올라가는 역추적이 필요합니다.

핵심 개념

시간·공간 복잡도

아이템 수 n, 용량 W일 때 표의 칸 수는 n×W개이고 각 칸은 O(1)에 계산되므로 시간복잡도는 O(nW)입니다. 표 전체를 저장하므로 공간복잡도도 O(nW)입니다.

피보나치와 무엇이 다른가 — 피보나치는 dp[i] 하나의 축만 있는 1차원 DP였지만, 배낭 문제는 dp[i][w]처럼 두 개의 축(아이템, 용량)이 필요한 2차원 DP입니다. 축이 늘어도 "포함 vs 제외 중 더 나은 것을 고른다"는 핵심 원리는 같습니다.
왜 "0/1"인가 — 같은 아이템을 여러 번 넣을 수 있다면 "분할 가능 배낭 문제"가 되어 그리디(algo-07)로도 풀 수 있지만, 0/1 배낭 문제는 각 아이템을 최대 한 번만 쓸 수 있어 그리디로는 최적해를 보장할 수 없어서 DP 같은 방법이 필요합니다.
왜 표의 순서가 중요한가 — dp[i][w]를 계산하려면 항상 바로 윗줄(dp[i-1][...])의 값이 먼저 계산되어 있어야 합니다. 그래서 행(아이템)을 위에서 아래로, 각 행 안에서는 용량을 왼쪽에서 오른쪽으로 채워나갑니다.
이 시각화에서 확인할 것 — "표 채우기" 탭에서 각 칸이 바로 위 칸(제외) 또는 대각선 위 칸(포함)을 참조해 채워지는 과정을, "선택 아이템 역추적" 탭에서 완성된 표에서 실제로 어떤 아이템이 배낭에 들어갔는지 확인하세요.

동적 계획법과 배낭 문제

동적 계획법(Dynamic Programming)은 큰 문제를 겹치는 작은 문제로 나누고, 작은 문제의 답을 저장해 다시 계산하지 않는 방법입니다. 1950년대에 리처드 벨만(Richard Bellman)이 정립하고 이름을 붙인 것으로 알려져 있고, 대표 저서는 『Dynamic Programming』(Princeton University Press, 1957)입니다. 0/1 배낭 문제는 이 방법을 표로 보여 주는 대표적인 예입니다.

숫자로 확인하기

이 시각화의 입력 — 아이템은 (무게, 가치) = (2, 3), (3, 4), (4, 5)이고 용량은 5입니다. 1번과 2번을 담으면 무게 5, 가치 7이 최적이고, 이 표는 3 × 5 = 15칸을 계산해 같은 답 7을 얻습니다.
그리디와의 차이 — 가치가 가장 큰 3번(가치 5, 무게 4)부터 담으면 남은 용량 1에 아무것도 못 넣어 총 가치가 5에 그칩니다. 최적(7)과 다릅니다.
크기가 커지면 — 아이템 n = 100개, 용량 W = 1,000,000이면 계산할 칸이 100 × 10⁶ = 10⁸개입니다. 용량 숫자가 커지면 칸 수가 그만큼 늘어나기 때문입니다.

자주 하는 오해

O(nW)는 다항 시간이라 효율적이다 — 입력의 길이는 W의 자릿수(약 log W)인데 시간은 W 값 자체에 비례하기 때문입니다. 그래서 O(nW)를 의사 다항 시간(pseudo-polynomial)이라고 부르고, 용량이 매우 큰 값이면 느려집니다.
DP는 반드시 표를 채우는 반복문이다 — 재귀에 계산 결과를 저장하는 메모이제이션(top-down)으로도 같은 문제를 풉니다. 이 시각화는 표를 채우는 bottom-up 방식입니다.
그리디로도 0/1 배낭을 풀 수 있다 — 무게 대비 가치 순으로 담는 그리디는 아이템을 쪼갤 수 있는 분할 가능 배낭에서는 최적이지만, 0/1에서는 최적을 보장하지 못합니다(이 시각화에서 가치가 큰 순으로 담으면 5로 최적 7에 못 미칩니다).
역추적 없이 표의 마지막 칸만 있으면 충분하다 — 마지막 칸은 최댓값만 알려 줍니다. 어떤 아이템을 골랐는지 알려면 표를 거슬러 올라가야 하고, 그러려면 표 전체를 남겨 두어야 합니다.

면접에서 이렇게 물어요

면접 질문

DP 문제인지 어떻게 알아보나요?

큰 문제의 답이 작은 문제의 답으로 만들어지고(최적 부분 구조), 같은 작은 문제가 여러 번 나오는지(겹치는 부분 문제)를 봅니다. 둘 다 있으면 저장해 재사용하는 DP가 효과적입니다.

면접 질문

0/1 배낭의 공간을 줄일 수 있나요?

최댓값만 필요하면 바로 윗줄만 있으면 되므로 한두 줄만 남겨 O(W) 공간으로 줄일 수 있습니다. 대신 어떤 아이템을 골랐는지 역추적하려면 표 전체가 필요합니다.

면접 질문

메모이제이션과 표 채우기(타뷸레이션)는 어떻게 다른가요?

메모이제이션은 재귀로 위에서 내려가며 필요한 부분 문제만 계산해 저장하고, 표 채우기는 작은 문제부터 순서대로 모두 계산합니다. 같은 점화식을 쓰지만 호출 깊이와 불필요한 계산이 달라집니다.

면접 질문

거스름돈 문제를 DP로 풀면 왜 그리디보다 확실한가요?

그리디는 매 순간 가장 큰 동전만 보지만 DP는 모든 금액의 최소 개수를 아래에서부터 쌓아 올려서, 동전 단위가 애매해도 최적을 보장합니다.

실제 시스템에서는

Python의 functools — functools.cache는 같은 인자로 다시 호출하면 저장된 결과를 돌려줍니다(인자는 해시 가능해야 합니다). lru_cache는 기본 maxsize가 128이라 오래 쓰지 않은 결과는 버려져 다시 계산될 수 있습니다. 메모이제이션을 직접 구현하지 않고 쓸 수 있습니다.
메모리 사용 — 표 전체를 저장하면 O(nW)의 메모리를 쓰기 때문에, 용량이 큰 문제에서는 필요한 행만 남기는 방식으로 줄이는 것이 중요합니다.
