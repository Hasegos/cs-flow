의존성 사슬 끊기 — 누산기 나누기

// 누산기 하나: 매 덧셈이 직전 덧셈의 결과를 기다림 (하나의 긴 의존성 사슬)
double sum = 0;
for (int i = 0; i < n; i++) sum += a[i];

// 누산기 넷: 서로 독립인 사슬 4개라 덧셈 여러 개가 겹쳐 진행될 수 있음
double s0 = 0, s1 = 0, s2 = 0, s3 = 0;
int i = 0;
for (; i + 3 < n; i += 4) {
    s0 += a[i];     s1 += a[i + 1];
    s2 += a[i + 2]; s3 += a[i + 3];
}
for (; i < n; i++) s0 += a[i]; // 4로 나누어떨어지지 않는 나머지
double total = s0 + s1 + s2 + s3;

부동소수점 덧셈은 결과가 나오기까지 여러 사이클이 걸립니다. 누산기가 하나면 매 반복이 직전 덧셈을 기다려야 해서 비순차 실행이 앞당길 명령어가 없습니다. 누산기를 넷으로 나누면 독립된 사슬이 4개가 되어 덧셈이 겹쳐 진행됩니다. 단, 부동소수점은 더하는 순서에 따라 결과가 아주 조금 달라질 수 있어서 컴파일러가 이렇게 자동으로 바꾸지 않는 경우가 많습니다.

메모리 지연을 숨길 수 있는 코드와 없는 코드

// 배열: 다음 원소의 주소를 이전 로드 결과 없이 계산할 수 있음 → 여러 로드를 겹쳐 실행
long total = 0;
for (int i = 0; i < n; i++) total += values[i];

// 연결 리스트: 다음 노드 주소가 이번 로드의 결과(p.next)에 들어 있음 → 로드끼리 사슬
for (Node p = head; p != null; p = p.next) total += p.value;

배열은 i번째 주소를 계산하는 데 앞선 로드의 결과가 필요 없어서, CPU가 캐시 미스 여러 개를 동시에 기다릴 수 있습니다(하드웨어 프리페치도 잘 동작합니다). 연결 리스트는 p.next를 읽어야 다음 주소를 알 수 있으므로 캐시 미스가 하나씩 차례로 일어나고, 비순차 실행도 그 사이에 할 일을 찾지 못합니다. 같은 개수의 원소를 더해도 리스트가 크게 느려질 수 있는 이유입니다.

레지스터 리네이밍 — 가짜 의존성 없애기

// 원래 명령어: r1이라는 이름을 두 번 사용
I1: r1 ← [a]         // 캐시 미스로 오래 걸림
I2: r2 ← r1 + 1       // I1의 결과를 읽음 (진짜 의존, RAW)
I3: r1 ← r5 × r6     // r1을 다시 씀: I2가 옛 r1을 읽기 전에 덮으면 안 됨 (WAR), I1과는 WAW
I4: r7 ← r1 - r8     // I3이 쓴 새 r1을 읽음 (진짜 의존, RAW)

// 리네이밍 후: 같은 r1이라도 쓸 때마다 다른 물리 레지스터(p1, p9)를 배정
I1: p1  ← [a]
I2: p2  ← p1 + 1
I3: p9  ← p5 × p6    // 이름이 달라져 I1, I2를 기다릴 필요가 없음
I4: p10 ← p9 - p8

프로그램에서 쓸 수 있는 레지스터 이름은 몇 개 되지 않아서 같은 이름이 계속 재사용됩니다. 리네이밍이 없으면 I3은 I2가 옛 r1을 읽을 때까지 기다려야 하지만, 새 물리 레지스터 p9에 쓰면 I1의 캐시 미스와 상관없이 바로 실행할 수 있습니다. 진짜 의존성(I1 → I2, I3 → I4)은 그대로 남습니다.
