float의 비트를 직접 꺼내 보기

float x = 6.5f;
int bits = Float.floatToIntBits(x);

int sign     = bits >>> 31;               // 부호 1비트
int exponent = (bits >>> 23) & 0xFF;      // 지수 8비트
int fraction = bits & 0x7FFFFF;          // 가수 23비트

// 6.5 → sign 0, exponent 129, fraction 5242880
double value = (sign == 0 ? 1 : -1)
        * (1 + fraction / Math.pow(2, 23))
        * Math.pow(2, exponent - 127);

Float.floatToIntBits는 float을 같은 비트 패턴의 int로 바꿔 줍니다. 최상위 비트가 부호, 그다음 8비트가 지수, 하위 23비트가 가수입니다. 정규화된 수는 가수 앞에 생략된 1을 붙여 1 + fraction / 2^23으로 읽고, 지수에서 바이어스 127을 빼서 2의 거듭제곱을 곱합니다. 이 식은 정규화된 수에만 맞고, 지수가 0이거나 255인 특수한 값(0, 비정규수, 무한대, NaN)은 별도로 해석해야 합니다.

실수 비교 — == 대신 허용 오차

double a = 0.1 + 0.2;
double b = 0.3;

System.out.println(a == b);                       // false
System.out.println(a);                            // 0.30000000000000004

double eps = 1e-9;
System.out.println(Math.abs(a - b) < eps);          // true

// 값의 크기에 비례하는 상대 오차로 비교
boolean close = Math.abs(a - b) <= eps * Math.max(Math.abs(a), Math.abs(b));

0.1 + 0.2는 0.30000000000000004라서 0.3과 ==로 비교하면 거짓입니다. 두 값의 차이가 허용 오차보다 작은지로 같음을 판단하는 것이 일반적입니다. 허용 오차는 값의 크기에 맞춰 정해야 합니다. 1e-9 같은 고정값은 값이 1 근처일 때는 알맞아도 아주 크거나 아주 작은 수에서는 너무 느슨하거나 너무 엄격할 수 있어, 큰 값에는 상대 오차를 씁니다. 어떤 허용 오차가 알맞은지는 계산의 성격에 달려 있으므로 정해진 정답은 없습니다.

정수가 건너뛰어지는 구간과 십진 계산

float big = 16777216f;                 // 2^24
System.out.println(big + 1 == big);          // true: float은 +1을 표현하지 못함

BigDecimal p = new BigDecimal("0.1");
BigDecimal q = new BigDecimal("0.2");
System.out.println(p.add(q));                    // 0.3 (정확한 십진 계산)

float은 2^24부터 이웃한 수의 간격이 2가 되어 16777216f + 1이 다시 16777216이 됩니다. 큰 수에 작은 수를 더하는 계산이 값을 바꾸지 못할 수 있다는 뜻입니다. 정확한 십진 계산이 필요하면 문자열로 만든 BigDecimal을 씁니다. 숫자 리터럴 0.1이 아니라 문자열 "0.1"로 만들어야 하는데, double 리터럴에서 만들면 이미 근사값이 들어가기 때문입니다. BigDecimal은 double보다 느리고 메모리를 더 쓰므로 정확한 십진 값이 필요한 곳에 한정해 씁니다.
