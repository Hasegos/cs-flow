2비트 포화 카운터 예측기

// 0,1 = not-taken 예측 / 2,3 = taken 예측
class TwoBitPredictor {
    private int counter = 3; // 3 = Strongly Taken

    boolean predict() {
        return counter >= 2;
    }

    void update(boolean taken) {
        if (taken) counter = Math.min(3, counter + 1);
        else       counter = Math.max(0, counter - 1);
    }
}

카운터가 3에서 한 번 not-taken을 만나도 2가 될 뿐이라 예측은 여전히 taken입니다. 반복문이 끝나는 순간 한 번만 틀리고, 다음 반복문 시작에서는 다시 맞춥니다.

분기 예측이 잘 되는 코드와 안 되는 코드

// 정렬된 데이터: 앞쪽은 전부 false, 뒤쪽은 전부 true → 패턴이 단순해 예측이 잘 맞음
long sum = 0;
for (int x : sortedData) {
    if (x >= 128) sum += x;
}

// 무작위 데이터: 조건이 매번 제멋대로라 예측이 자주 틀림 → 같은 코드인데 더 느림
for (int x : randomData) {
    if (x >= 128) sum += x;
}

똑같은 반복문이어도 데이터를 정렬해 두면 분기 결과가 길게 한 방향으로 이어져 예측이 잘 맞습니다. 무작위 데이터에서는 예측 실패가 잦아 flush가 반복되어 느려질 수 있습니다.

분기를 없애는 방법 — 조건부 이동

// 분기가 있는 형태: 조건마다 예측이 필요
if (x >= 128) sum += x;

// 분기 없는 형태: 조건을 0 또는 1 마스크로 바꿔 계산 (예측할 필요가 없음)
int mask = ~((x - 128) >> 31); // x >= 128 이면 전부 1, 아니면 0
sum += x & mask;

분기가 예측하기 어렵다면 조건부 이동이나 비트 연산으로 분기 자체를 없애는 방법이 있습니다. 컴파일러도 간단한 조건은 cmov 같은 명령으로 바꿔 분기를 제거하기도 합니다.
