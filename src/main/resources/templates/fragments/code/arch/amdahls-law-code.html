암달의 법칙 공식을 그대로 코드로

// Speedup(N) = 1 / ((1 - p) + p / N)
static double speedup(double p, int cores) {
    return 1.0 / ((1.0 - p) + p / cores);
}

speedup(0.8, 1);    // 1.00
speedup(0.8, 8);    // 3.33
speedup(0.8, 1024); // 약 4.98 — 상한 5.0에 수렴

병렬 비율 p가 0.8이면 코어를 1024개로 늘려도 5배를 넘을 수 없습니다. 코어를 8개에서 1024개로 128배 늘렸는데 속도 향상은 3.33배에서 4.98배로 늘어나는 데 그칩니다.

병렬 구간과 직렬 구간이 섞인 실제 코드

// 병렬 구간: 각 요소를 서로 독립적으로 처리 — 코어를 늘리면 빨라짐
long sum = data.parallelStream()
                .mapToLong(x -> heavy(x))
                .sum();

// 직렬 구간: 파일 쓰기처럼 순서대로 한 번에 하나씩 — 코어를 늘려도 그대로
writeResultToFile(sum);

heavy(x) 계산은 코어 수만큼 나눠 처리되지만, 결과를 파일에 쓰는 구간은 코어를 늘려도 줄지 않습니다. 이 직렬 구간이 전체 시간에서 차지하는 비율이 곧 1-p이고, 속도 향상의 상한을 결정합니다.

일부만 s배 빨라졌을 때 — 일반화된 형태

// 전체 중 비율 f 만 s배 빨라졌을 때의 전체 속도 향상
static double overall(double f, double s) {
    return 1.0 / ((1.0 - f) + f / s);
}

overall(0.4, 10); // 약 1.56 — 전체의 40%를 10배 빠르게 해도 전체는 1.56배

병렬화가 아니라 "특정 연산을 하드웨어로 가속" 같은 경우에도 똑같이 적용됩니다. 전체의 40%만 10배 빨라져도 나머지 60%가 그대로여서 전체 향상은 1.56배에 그칩니다.
