Java — 선형 탐색 (비교 기준)

/* ── 처음부터 하나씩 확인 — 정렬 여부와 무관하게 동작 ─────── */
public int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) return i;   // 찾으면 인덱스 반환
    }
    return -1;                              // 끝까지 못 찾음
}

최악의 경우(target이 맨 끝에 있거나 없을 때) arr.length번, 즉 O(n)만큼 비교해야 합니다.
정렬 여부와 상관없이 항상 동작하지만, 데이터가 이미 정렬되어 있다면 이진 탐색보다 훨씬 비효율적입니다.

Java — 이진 탐색 (반복문)

/* ── 정렬된 배열 전제: 매 단계 범위를 절반으로 좁힘 ────────── */
public int binarySearch(int[] arr, int target) {
    int low = 0, high = arr.length - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;   // 오버플로 방지 계산
        if (arr[mid] == target) {
            return mid;                    // 발견
        } else if (arr[mid] < target) {
            low = mid + 1;                 // 오른쪽 절반만 다시 탐색
        } else {
            high = mid - 1;                // 왼쪽 절반만 다시 탐색
        }
    }
    return -1;                              // low > high → 존재하지 않음
}

low <= high인 동안 매 반복마다 범위가 절반으로 줄어들기 때문에, 최악의 경우에도 log₂n번이면 반복이 끝납니다.
n=16이면 최대 4번, n=1,000,000이면 최대 약 20번 — 반복 횟수가 n이 아니라 n의 로그에 비례하는 O(log n) 시간복잡도입니다.

Java — 이진 탐색 (재귀)

/* ── 반복문 대신 재귀 호출로 같은 로직을 표현 ──────────────── */
public int binarySearchRecursive(int[] arr, int target, int low, int high) {
    if (low > high) return -1;             // 기저 사례: 더 볼 범위가 없음

    int mid = low + (high - low) / 2;
    if (arr[mid] == target) {
        return mid;
    } else if (arr[mid] < target) {
        return binarySearchRecursive(arr, target, mid + 1, high);   // 오른쪽 절반 재귀
    } else {
        return binarySearchRecursive(arr, target, low, mid - 1);    // 왼쪽 절반 재귀
    }
}

반복문 버전과 시간복잡도는 동일하게 O(log n)이지만, 매 호출마다 범위가 절반으로 줄어들기 때문에 재귀 호출 깊이도 log₂n에 비례합니다.
ds-10(동적 프로그래밍)에서 다룬 재귀와 달리 매번 부분 문제가 하나뿐이라 중복 계산이 없어, 메모이제이션 같은 별도의 캐시가 필요하지 않습니다.
