Java — 병합 정렬 (Merge Sort)

/* ── 절반으로 나누고, 정렬된 두 절반을 다시 합침 ───────────── */
public void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;              // 기저 사례: 원소 1개는 이미 정렬됨

    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);            // 왼쪽 절반 정렬
    mergeSort(arr, mid + 1, right);       // 오른쪽 절반 정렬
    merge(arr, left, mid, right);        // 정렬된 두 절반을 합침
}

배열을 계속 절반으로 나누면 깊이는 log₂n, 각 깊이에서 merge가 전체 원소를 한 번씩 비교·복사하므로 O(n)입니다.
깊이(log n) × 각 단계 작업량(n) = O(n log n)이며, 항상 정확히 절반씩 나누기 때문에 입력에 상관없이 이 시간이 보장됩니다.

Java — 퀵 정렬 (Quick Sort, Lomuto 파티션)

/* ── 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 모음 ──────── */
public void quickSort(int[] arr, int lo, int hi) {
    if (lo >= hi) return;

    int pivot = arr[hi];                  // 구간의 마지막 값을 피벗으로 사용
    int i = lo - 1;
    for (int j = lo; j < hi; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(arr, i, j);              // 피벗보다 작은 값을 앞쪽으로 이동
        }
    }
    swap(arr, i + 1, hi);              // 피벗을 최종 위치로 이동

    int p = i + 1;
    quickSort(arr, lo, p - 1);
    quickSort(arr, p + 1, hi);
}

피벗이 매번 배열을 절반에 가깝게 나누면 병합 정렬처럼 O(n log n)이지만, arr[j] < pivot 비교 결과에 따라 분할 비율이 달라지는 것이 병합 정렬과의 차이입니다.
평균적으로는 O(n log n)이지만, 이미 정렬된 배열에서 항상 마지막 값을 피벗으로 고르면 매번 원소 1개씩만 떼어내는 최악의 경우 O(n²)가 될 수 있습니다.

Java — 힙 정렬 (Heap Sort)

/* ── 최대 힙을 만든 뒤, 루트(최댓값)를 하나씩 꺼내 정렬 ────── */
public void heapSort(int[] arr) {
    int n = arr.length;
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(arr, i, n);             // 배열 전체를 최대 힙으로 구성 — O(n)
    }
    for (int end = n - 1; end > 0; end--) {
        swap(arr, 0, end);              // 루트(최댓값)를 정렬 영역 맨 앞으로
        siftDown(arr, 0, end);         // 줄어든 힙을 다시 정리
    }
}

siftDown 한 번은 힙의 높이(log n)만큼만 비교하면 되므로, n개를 하나씩 꺼내며 매번 siftDown을 호출해도 전체는 O(n log n)입니다.
병합 정렬처럼 최선·평균·최악이 모두 O(n log n)으로 안정적이면서도, 퀵 정렬처럼 추가 배열 없이 원본 배열 안에서 정렬을 끝내는 제자리 정렬이라는 점이 특징입니다.
