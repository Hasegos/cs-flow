Java — 0/1 배낭 문제 (2차원 DP 테이블)

/* ── dp[i][w]: 처음 i개 아이템, 용량 w일 때의 최대 가치 ──── */
public int knapsack(int[] weights, int[] values, int capacity) {
    int n = weights.length;
    int[][] dp = new int[n + 1][capacity + 1];   // 0행·0열은 자동으로 0(기저 사례)

    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= capacity; w++) {
            int without = dp[i - 1][w];              // 이 아이템을 제외했을 때
            int with = (weights[i - 1] <= w)
                ? dp[i - 1][w - weights[i - 1]] + values[i - 1]   // 포함했을 때
                : -1;                                // 무게 초과 — 포함 불가
            dp[i][w] = Math.max(without, with);
        }
    }
    return dp[n][capacity];
}

without은 바로 위 칸(dp[i-1][w])을, with는 대각선 위 칸(dp[i-1][w-무게])을 참조합니다 — 두 칸 모두 "이미 계산된 이전 줄"이라 순서대로 채우면 항상 값이 준비되어 있습니다.
무게가 용량을 넘으면 애초에 넣을 수 없으므로 with를 계산 자체를 하지 않고(-1로 처리) without만 남습니다.

Java — 선택 아이템 역추적

/* ── 완성된 표를 오른쪽 아래에서 왼쪽 위로 거슬러 올라감 ───── */
public List<Integer> findSelectedItems(int[][] dp, int[] weights, int n, int capacity) {
    List<Integer> selected = new ArrayList<>();
    int w = capacity;

    for (int i = n; i >= 1; i--) {
        if (dp[i][w] != dp[i - 1][w]) {         // 값이 다르면 이 아이템 덕분에 달라진 것
            selected.add(0, i - 1);           // 아이템 (i-1)을 포함했다고 기록
            w -= weights[i - 1];              // 그만큼 용량을 되돌려 계속 거슬러 올라감
        }
        // 값이 같으면 이 아이템은 포함되지 않은 것 — w는 그대로 두고 한 줄 위로
    }
    return selected;
}

dp[i][w] != dp[i-1][w]가 핵심입니다 — 아이템 i를 고려하기 전(i-1)과 후(i)의 값이 달라졌다면, 그 차이는 아이템 i를 포함했기 때문입니다.
포함으로 판단되면 용량 w에서 그 아이템의 무게만큼을 빼고 한 줄 위로 이동합니다 — "이 아이템을 빼면 얼마가 남았어야 하는지"를 거슬러 올라가는 것입니다.

Java — 공간 최적화 (1차원 배열, O(W) 공간)

/* ── 매 행이 바로 이전 행만 참조하므로 배열 1개로 축소 가능 ── */
public int knapsackOptimized(int[] weights, int[] values, int capacity) {
    int[] dp = new int[capacity + 1];

    for (int i = 0; i < weights.length; i++) {
        for (int w = capacity; w >= weights[i]; w--) {   // 반드시 오른쪽에서 왼쪽으로!
            dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
        }
    }
    return dp[capacity];
}

2차원 표의 각 행은 바로 위 행만 참조하므로, 배열 하나를 재사용하면 공간을 O(nW)에서 O(W)로 줄일 수 있습니다 — ds-10(동적 프로그래밍 기초)에서 피보나치를 변수 2개로 줄인 것과 같은 최적화 원리입니다.
단, 용량을 큰 값에서 작은 값 순서로 갱신해야 합니다.
왼쪽에서 오른쪽으로 갱신하면 같은 아이템을 여러 번 포함하는 것과 같은 효과가 생겨(0/1이 아니라 무제한이 되어) 답이 달라집니다.
이 시각화의 역추적 기능은 2차원 표가 있어야 가능해, 코드 탭에서는 참고용으로만 소개합니다.
