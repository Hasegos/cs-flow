Java — BFS (너비 우선 탐색, 큐)

/* ── 큐(Queue): 먼저 들어온 노드를 먼저 꺼냄(FIFO) ─────────── */
public List<Integer> bfs(int start, List<List<Integer>> adj) {
    List<Integer> order = new ArrayList<>();
    boolean[] visited = new boolean[adj.size()];
    Queue<Integer> queue = new LinkedList<>();

    queue.offer(start);
    visited[start] = true;

    while (!queue.isEmpty()) {
        int cur = queue.poll();          // 큐의 맨 앞에서 꺼냄
        order.add(cur);
        for (int next : adj.get(cur)) {
            if (!visited[next]) {
                visited[next] = true;      // 발견 즉시 방문 표시(중복 방지)
                queue.offer(next);        // 큐의 맨 뒤에 추가
            }
        }
    }
    return order;
}

queue.poll()은 항상 가장 먼저 들어온(=시작 노드에서 가장 가까운) 노드를 꺼내기 때문에, 방문 순서가 자연스럽게 "가까운 노드부터" 층 단위로 퍼집니다.
방문 표시를 queue.offer() 시점(발견 즉시)에 하는 것이 핵심입니다 — 방문 시점에 표시하면 같은 노드가 큐에 중복으로 쌓일 수 있습니다.

Java — DFS (깊이 우선 탐색, 스택)

/* ── 스택(Stack): 가장 나중에 들어온 노드를 먼저 꺼냄(LIFO) ── */
public List<Integer> dfs(int start, List<List<Integer>> adj) {
    List<Integer> order = new ArrayList<>();
    boolean[] visited = new boolean[adj.size()];
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);

    while (!stack.isEmpty()) {
        int cur = stack.pop();          // 스택의 맨 위(가장 최근)에서 꺼냄
        if (visited[cur]) continue;     // 중복으로 쌓였던 노드는 건너뜀
        visited[cur] = true;
        order.add(cur);
        for (int next : adj.get(cur)) {
            if (!visited[next]) stack.push(next);
        }
    }
    return order;
}

BFS 코드와 비교해보면 Queue가 Deque(스택)으로, poll()이 pop()으로 바뀐 것 외에는 구조가 거의 동일합니다.
방문 표시를 pop() 시점(꺼낼 때)으로 옮긴 이유는, 스택은 같은 노드가 여러 경로로 중복 push될 수 있어 꺼낼 때 한 번 더 확인이 필요하기 때문입니다.

Java — DFS (재귀 버전, 스택과 동일한 원리)

/* ── 재귀 호출도 결국 시스템이 관리하는 스택을 사용함 ─────── */
public void dfsRecursive(int cur, boolean[] visited, List<List<Integer>> adj, List<Integer> order) {
    visited[cur] = true;
    order.add(cur);
    for (int next : adj.get(cur)) {
        if (!visited[next]) {
            dfsRecursive(next, visited, adj, order);   // 한 갈래를 끝까지 파고든 뒤 되돌아옴
        }
    }
}

반복문 + 명시적 스택 버전과 방문 순서가 완전히 같습니다 — dfsRecursive가 자신을 호출할 때마다 함수 호출 스택에 쌓이고,
더 갈 곳이 없으면 스택에서 빠져나오며(return) 이전 갈래로 되돌아가기 때문입니다.
ds-10(동적 프로그래밍)에서 다룬 재귀와 마찬가지로, 그래프에 사이클이 있다면 반드시 visited 체크가 있어야 무한 재귀에 빠지지 않습니다.
