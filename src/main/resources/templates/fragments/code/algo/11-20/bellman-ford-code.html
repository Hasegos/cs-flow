Python — 벨만-포드와 음수 사이클 탐지

INF = float('inf')

def bellman_ford(n, edges, src):
    dist = [INF] * n
    dist[src] = 0
    for _ in range(n - 1):                       # V-1번 반복
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w              # 완화(relax)
    for u, v, w in edges:                          # 한 번 더 확인
        if dist[u] != INF and dist[u] + w < dist[v]:
            return None                           # 음수 사이클
    return dist

# S=0, A=1, B=2, C=3, D=4 · (출발, 도착, 가중치)
E = [(3, 4, 2), (2, 3, 4), (1, 2, -3), (0, 1, 4),
     (0, 2, 5), (1, 3, 8), (2, 4, 7)]
print(bellman_ford(5, E, 0))                       # [0, 4, 1, 5, 7]
print(bellman_ford(5, E + [(2, 1, 1)], 0))         # None  (A → B → A 합 -2)

벨만-포드는 모든 간선을 한 번씩 완화하는 일을 V-1번 반복합니다. 완화는 출발 쪽 거리에 가중치를 더한 값이 도착 쪽의 현재 거리보다 작으면 도착 쪽 거리를 그 값으로 줄이는 연산입니다. 음수 가중치 간선 A → B(-3)이 있어도 정답 [0, 4, 1, 5, 7]이 나옵니다. 다익스트라는 거리를 한 번 확정하면 고치지 않기 때문에 이런 그래프에서 틀릴 수 있습니다. 음수 사이클이 없으면 최단 경로는 간선을 많아야 V-1개 지나므로 V-1번이면 거리가 확정됩니다. 그 뒤 한 번 더 확인했을 때도 줄어드는 간선이 있으면 출발 정점에서 닿을 수 있는 음수 사이클이 있다는 뜻이고, 함수는 None을 돌려줍니다. 간선 B → A(1)을 더하면 A → B → A의 합이 -3 + 1 = -2라 음수 사이클이 생겨 None이 나옵니다. 시각화의 라운드 반복 탭과 음수 사이클 탭이 보여 주는 과정과 같고, 간선 E개를 V번 훑으므로 O(VE)입니다.

Python — 일찍 끝내기와 간선 순서의 영향

def bellman_ford(n, edges, src):
    dist = [INF] * n
    dist[src] = 0
    rounds = 0
    for _ in range(n - 1):
        rounds += 1
        changed = False
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:                              # 한 라운드 동안 갱신이 없으면 끝
            break
    for u, v, w in edges:
        if dist[u] != INF and dist[u] + w < dist[v]:
            return None, rounds
    return dist, rounds

print(bellman_ford(5, E, 0))                       # ([0, 4, 1, 5, 7], 4)
good = [(0, 1, 4), (1, 2, -3), (0, 2, 5), (2, 3, 4),
        (1, 3, 8), (2, 4, 7), (3, 4, 2)]
print(bellman_ford(5, good, 0))                    # ([0, 4, 1, 5, 7], 2)

한 라운드 동안 갱신이 하나도 없으면 이후 라운드에서도 거리가 변하지 않으므로 V-1번을 채우지 않고 끝낼 수 있습니다. 이 조기 종료를 넣으면 간선을 확인하는 순서가 라운드 수에 영향을 줍니다. 같은 그래프에서 간선을 앞쪽 정점에서 뒤쪽 정점 쪽으로 가는 순서(S → A, A → B, …)로 놓으면 라운드 1에서 모든 거리가 확정되고 라운드 2에서 갱신이 없음을 확인하며 끝납니다. 시각화처럼 불리한 순서로 놓으면 4라운드가 모두 필요합니다. 최악의 경우는 순서와 상관없이 V-1번이라 시간 복잡도는 그대로 O(VE)입니다.

Java — 벨만-포드

record Edge(int from, int to, int w) {}

static final int INF = Integer.MAX_VALUE;

static int[] bellmanFord(int n, List<Edge> edges, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, INF);
    dist[src] = 0;
    for (int i = 0; i < n - 1; i++) {
        for (Edge e : edges) {
            if (dist[e.from()] != INF && dist[e.from()] + e.w() < dist[e.to()]) {
                dist[e.to()] = dist[e.from()] + e.w();
            }
        }
    }
    for (Edge e : edges) {                          // 음수 사이클 확인
        if (dist[e.from()] != INF && dist[e.from()] + e.w() < dist[e.to()]) {
            return null;
        }
    }
    return dist;
}

// 같은 그래프: [0, 4, 1, 5, 7], B → A(1)을 더하면 null

자바 버전도 구조가 같습니다. INF를 Integer.MAX_VALUE로 두면 INF에 양의 가중치를 더할 때 넘쳐 음수가 되고, 음의 가중치를 더하면 INF보다 작아져 닿지 못한 정점이 갱신된 것처럼 됩니다. 그래서 출발 쪽 거리가 INF가 아닐 때만 더하도록 검사합니다. 위의 파이썬 예와 같은 그래프에서 결과는 [0, 4, 1, 5, 7]이고, B → A(1) 간선을 더하면 확인 단계에서 null을 돌려줍니다. 실무에서는 음수 가중치가 없다면 보통 다익스트라가 더 빠르지만, 환율이나 비용처럼 음수 간선이 생길 수 있는 문제나 음수 사이클 자체를 찾고 싶은 문제에는 벨만-포드를 씁니다.
