Python — 부분집합 합: 찾기와 검증

from collections import Counter

def verify(nums, target, cert):                    # 인증서 검증: 다항 시간
    return not (Counter(cert) - Counter(nums)) and sum(cert) == target

def find(nums, target):                            # 답 찾기: 부분집합 2^n개를 확인
    n = len(nums)
    for mask in range(1 << n):
        sub = [nums[i] for i in range(n) if mask >> i & 1]
        if sum(sub) == target:
            return sub, mask + 1                  # (부분집합, 확인한 개수)
    return None, 1 << n

nums = [3, 34, 4, 12, 5, 2]
print(find(nums, 9))                           # ([4, 5], 21)
print(verify(nums, 9, [4, 5]), verify(nums, 9, [3, 34]))   # True False
print(find(nums, 13))                          # (None, 64)

NP의 정의를 코드로 옮긴 예입니다. NP는 답(인증서)이 주어졌을 때 그 답이 맞는지 다항 시간에 검증할 수 있는 결정 문제의 집합입니다. verify는 인증서가 nums의 원소로만 이루어졌는지 확인하고 합을 목표와 비교하는 것이 전부라 입력 크기의 다항식 시간이면 됩니다. find는 답을 직접 찾는 쪽으로, 원소가 n개이면 부분집합 2^n개를 하나씩 확인합니다(부분집합 하나를 만드는 O(n) 비용은 생략한 단순화입니다). 시각화의 순서로는 21번째에서 [4, 5]를 찾지만, 합이 13인 부분집합은 없어서 64개를 모두 확인하고서야 없다는 결론이 납니다. 여기서의 find는 가장 단순한 완전 탐색이며, 부분집합 합이 다항 시간에 풀리는지는 알려져 있지 않습니다. 시각화의 찾기와 검증 탭이 보여 주는 과정과 같습니다.

Python — 환원: 클리크를 정점 덮개로 바꾸기

from itertools import combinations

V = {0, 1, 2, 3, 4}
E = {(0, 1), (0, 2), (1, 2), (2, 3), (3, 4)}

def is_clique(E, C):
    return all((a, b) in E or (b, a) in E for a, b in combinations(sorted(C), 2))

def complement(V, E):                          # 입력 변환: 보완 그래프를 만든다
    return {(a, b) for a, b in combinations(sorted(V), 2) if (a, b) not in E and (b, a) not in E}

def is_vertex_cover(E, S):
    return all(a in S or b in S for a, b in E)

Ec = complement(V, E)
C = {0, 1, 2}                                    # 크기 3인 클리크
print(is_clique(E, C), sorted(Ec), is_vertex_cover(Ec, V - C), len(V) - len(C))
# True [(0, 3), (0, 4), (1, 3), (1, 4), (2, 4)] True 2
print(is_clique(E, {2, 3, 4}), is_vertex_cover(Ec, V - {2, 3, 4}))   # False False

환원 A ≤p B는 A의 입력을 다항 시간에 B의 입력으로 바꾸어 B의 답이 곧 A의 답이 되게 하는 변환입니다. 여기서는 클리크를 정점 덮개로 바꿉니다. 그래프 G에서 정점 집합 C가 클리크라는 것은 보완 그래프(G에 없는 간선을 모은 그래프)에서 V - C가 정점 덮개라는 것과 같습니다. 5개 정점 그래프에서 C = {0, 1, 2}는 클리크이고 V - C = {3, 4}는 보완 그래프의 모든 간선을 덮으며, 크기도 |V| - |C| = 2입니다. {2, 3, 4}는 클리크가 아니고 V - C도 덮개가 아닙니다. 보완 그래프를 만드는 일은 정점 쌍을 한 번씩 보는 다항 시간이라 이 변환은 다항 시간입니다. 어느 한쪽이 다항 시간에 풀리면 다른 쪽도 풀리므로, 한쪽이 NP-완전이면 다른 쪽이 NP에 속하는 한 같이 NP-완전이 됩니다. 시각화의 환원 탭에서 클리크 다음에 정점 덮개가 나오는 화살표가 이 변환입니다.

Java — 부분집합 합 찾기와 검증

static boolean verify(int[] nums, int target, int[] cert) {
    List<Integer> pool = new ArrayList<>();
    for (int x : nums) pool.add(x);
    int sum = 0;
    for (int c : cert) {
        if (!pool.remove((Integer) c)) return false;   // 집합에 없는 원소(또는 중복 사용)
        sum += c;
    }
    return sum == target;
}

static int[] find(int[] nums, int target, int[] checked) {
    int n = nums.length;
    for (int mask = 0; mask < (1 << n); mask++) {
        int sum = 0;
        for (int i = 0; i < n; i++) if ((mask >> i & 1) == 1) sum += nums[i];
        checked[0]++;
        if (sum == target) return pick(nums, mask);
    }
    return null;
}

static int[] pick(int[] nums, int mask) {          // 켜진 비트의 원소만 모은다
    return IntStream.range(0, nums.length).filter(i -> (mask >> i & 1) == 1).map(i -> nums[i]).toArray();
}

// nums = {3, 34, 4, 12, 5, 2}: find(target 9) → [4, 5] (확인 21번), verify(nums, 9, {4, 5}) → true
// find(target 13) → null (확인 64번)

같은 구조를 자바로 쓴 것입니다. 비트마스크의 각 비트가 원소를 넣을지 말지를 뜻하므로 1 << n개의 부분집합을 차례로 만들 수 있습니다. pick은 켜진 비트에 해당하는 원소를 배열로 모으는 보조 함수입니다. 검증 verify는 인증서 원소를 풀에서 하나씩 빼며 더해 비교하는 반복문이고, 찾기 find는 그 앞에 부분집합 개수만큼의 바깥 반복이 있습니다. n이 커질수록 find의 비용은 2^n으로 빠르게 늘지만 verify는 인증서 크기에 비례합니다. 이 차이가 NP 문제의 특징이며, 실무에서 NP-완전 문제를 만나면 근사 알고리즘, 휴리스틱, 입력이 작을 때의 완전 탐색 같은 방법을 고려합니다.
