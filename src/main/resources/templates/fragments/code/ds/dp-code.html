Java — 완전 탐색 (재귀)

/* ── 완전 탐색: 저장 없이 매번 새로 재귀 호출 ─────────────── */
public int fibNaive(int n) {
    if (n <= 1) return n;              // 기저 사례
    return fibNaive(n - 1) + fibNaive(n - 2);
}

코드는 단 세 줄이지만, fib(n-2)가 fib(n-1) 내부에서도 다시 호출되는 식으로 같은 부분 문제가 기하급수적으로 반복됩니다.
호출 횟수는 대략 fib(n)에 비례해 늘어나 시간복잡도가 O(2ⁿ)에 가까워지고, n이 40만 넘어가도 체감될 만큼 느려집니다.

Java — 메모이제이션 (Top-down)

/* ── 메모이제이션: 재귀 구조 + 캐시로 중복 계산 제거 ──────── */
private Map<Integer, Integer> memo = new HashMap<>();

public int fibMemo(int n) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);   // 캐시 적중 → 재귀 없이 즉시 반환

    int result = fibMemo(n - 1) + fibMemo(n - 2);
    memo.put(n, result);                          // 계산 결과를 캐시에 저장
    return result;
}

fibNaive와 재귀 구조는 동일하지만, memo.containsKey(n) 한 줄이 결정적인 차이를 만듭니다 — 이미 계산된 n이면 재귀 호출 자체가 일어나지 않습니다.
각 n은 정확히 한 번만 계산되므로 시간복잡도가 O(n)으로 줄어듭니다. 다만 재귀 호출 스택과 캐시(Map)를 함께 쓰므로 공간복잡도는 O(n)입니다.

Java — 타뷸레이션 (Bottom-up)

/* ── 타뷸레이션: 재귀 없이 표를 아래에서부터 채움 ─────────── */
public int fibTab(int n) {
    if (n <= 1) return n;

    int[] dp = new int[n + 1];
    dp[0] = 0;
    dp[1] = 1;                                // 기저 사례를 먼저 채움

    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];       // 이전 두 값으로 다음 값 계산
    }
    return dp[n];
}

/* ── 참고: dp[i]는 직전 두 값에만 의존 → 변수 2개로 O(1) 공간 가능 ─ */
public int fibOptimized(int n) {
    if (n <= 1) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}

재귀가 전혀 없어 호출 스택이 쌓이지 않으므로 큰 n에서도 StackOverflowError 걱정이 없고, 반복문 하나로 끝나 실전에서 메모이제이션보다 대체로 더 빠릅니다.
시간복잡도는 O(n)으로 메모이제이션과 같지만, fibOptimized처럼 직전 두 값만 유지하면 배열 전체(O(n))가 아닌 변수 두 개(O(1))만으로도 충분합니다.
