Java — 그래프 정의 (인접 리스트)

/* ── 그래프 정의: 정점(Integer) → 인접 정점 목록(List) ──── */
public class Graph {
    private final Map<Integer, List<Integer>> adj = new HashMap<>();

    public void addVertex(int v) {
        adj.putIfAbsent(v, new ArrayList<>());
    }

    // 무방향 그래프: 간선 하나를 양쪽 정점 리스트에 모두 추가합니다.
    public void addEdge(int v1, int v2) {
        addVertex(v1);
        addVertex(v2);
        adj.get(v1).add(v2);
        adj.get(v2).add(v1);
    }

    public List<Integer> neighbors(int v) {
        return adj.getOrDefault(v, Collections.emptyList());
    }
}

인접 리스트는 정점마다 연결된 정점의 목록만 저장하므로 공간복잡도가 O(V+E)입니다.
반면 인접 행렬은 boolean[][] matrix = new boolean[V][V] 형태로 O(V²) 공간을 사용하는 대신, matrix[i][j] 조회가 O(1)로 빠릅니다.
정점 수 대비 간선이 적은 희소 그래프에서는 인접 리스트가, 간선이 많은 밀집 그래프이거나 빠른 조회가 중요하면 인접 행렬이 유리합니다.

Java — BFS (너비 우선 탐색, Queue)

/* ── BFS: 큐(Queue, FIFO)를 이용해 가까운 정점부터 방문 ──── */
public List<Integer> bfs(Graph graph, int start) {
    List<Integer> visitOrder = new ArrayList<>();
    Set<Integer> visited = new HashSet<>();
    Queue<Integer> queue = new LinkedList<>();

    visited.add(start);            // 큐에 넣을 때 바로 방문 처리
    queue.offer(start);

    while (!queue.isEmpty()) {
        int cur = queue.poll();
        visitOrder.add(cur);          // 1. 방문 순서에 추가

        for (int next : graph.neighbors(cur)) {
            if (!visited.contains(next)) {
                visited.add(next);      // 2. 중복 삽입 방지를 위해 미리 방문 처리
                queue.offer(next);
            }
        }
    }
    return visitOrder;
}

핵심은 visited.add(next)를 큐에 offer하는 시점에 실행하는 것입니다.
꺼낼 때(poll) 방문 처리하면 같은 정점이 큐에 여러 번 들어가 중복 방문이 발생할 수 있습니다.
시간복잡도는 모든 정점과 간선을 정확히 한 번씩 확인하므로 O(V+E), 공간복잡도는 큐와 visited 집합을 위한 O(V)입니다.
가중치가 없는 그래프에서 시작 정점으로부터의 최단 경로(간선 수 기준)를 구할 때도 BFS가 사용됩니다.

Java — DFS (깊이 우선 탐색, 재귀)

/* ── DFS: 재귀 호출 스택(LIFO)을 이용해 깊이 먼저 탐색 ───── */
public void dfs(Graph graph, int cur, Set<Integer> visited, List<Integer> visitOrder) {
    visited.add(cur);              // 1. 진입 즉시 방문 처리 (호출 스택에 push)
    visitOrder.add(cur);

    for (int next : graph.neighbors(cur)) {
        if (!visited.contains(next)) {
            dfs(graph, next, visited, visitOrder);  // 2. 재귀 호출
        }
    }
}                                       // 3. 함수 종료 시 호출 스택에서 pop

/* ── 호출 예시 ──────────────────────────────────────────── */
List<Integer> result = new ArrayList<>();
dfs(graph, start, new HashSet<>(), result);

트리의 전위 순회와 원리가 같습니다 — 방문하자마자 처리하고, 미방문 인접 정점으로 재귀 호출합니다.
시간복잡도는 O(V+E)로 BFS와 동일하지만, 재귀 호출 스택 깊이는 그래프의 형태에 따라 최악의 경우 O(V)까지 늘어나 정점 수가 매우 많으면 StackOverflowError 위험이 있습니다.

Java — 반복적 DFS (명시적 스택, 참고)

/* ── 반복적 DFS: 재귀 대신 명시적 스택(Deque) 사용 ──────── */
// 재귀 DFS의 StackOverflowError 위험을 피할 때 사용합니다.
public List<Integer> dfsIterative(Graph graph, int start) {
    List<Integer> visitOrder = new ArrayList<>();
    Set<Integer> visited = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>();

    stack.push(start);

    while (!stack.isEmpty()) {
        int cur = stack.pop();
        if (visited.contains(cur)) continue;   // BFS와 달리 pop 시점에 중복 검사
        visited.add(cur);
        visitOrder.add(cur);

        for (int next : graph.neighbors(cur)) {
            if (!visited.contains(next)) stack.push(next);
        }
    }
    return visitOrder;
}

BFS는 큐에 offer하는 시점에 방문 처리해 중복 삽입을 막지만, 이 반복적 DFS는 스택에 같은 정점이 여러 번 쌓일 수 있어 pop 시점에 방문 여부를 다시 검사합니다.
이번 시각화의 핵심 범위는 재귀 DFS이지만, 재귀 호출 스택과 명시적 스택이 결국 같은 개념(LIFO)이라는 점을 이해하는 데 참고가 됩니다.
