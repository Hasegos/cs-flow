Java — 배열 직접 구현 vs ArrayList

/* ── 고정 배열 — 인덱스 직접 접근 ─────────────────────── */
int[] arr = new int[5];          // 크기 고정, 연속 메모리 할당
arr[0] = 10; arr[1] = 30;        // O(1) 임의 접근

/* ── 중간 삽입: O(n) — 원소 이동 필요 ──────────────────── */
public static void insertAt(int[] arr, int idx, int val, int size) {
    // 뒤에서부터 한 칸씩 오른쪽으로 이동
    for (int i = size - 1; i >= idx; i--) {
        arr[i + 1] = arr[i];
    }
    arr[idx] = val;
}

/* ── 동적 배열 ArrayList — 내부는 배열, 크기 자동 조정 ──── */
List<Integer> list = new ArrayList<>();
list.add(10);                      // Amortized O(1) — 공간 초과 시 2배 재할당
list.add(1, 20);                  // O(n) — 이후 원소 이동
list.get(0);                      // O(1) — 인덱스 직접 접근
list.remove(0);                   // O(n) — 이후 원소 앞으로 이동

// ArrayList 내부 재할당 원리
// DEFAULT_CAPACITY = 10, 초과 시 newCapacity = oldCapacity * 1.5
// Arrays.copyOf()로 새 배열에 복사 후 참조 교체

/* ── 배열 이진 탐색 — 정렬된 배열에서 O(log n) ─────────── */
int[] sorted = {10, 20, 30, 40, 50};
int idx = Arrays.binarySearch(sorted, 30); // idx = 2

배열은 메모리에 연속으로 저장되므로 arr[i] 접근은 시작 주소 + i × 타입크기로 계산해 O(1)입니다.
중간 삽입·삭제는 이후 원소를 이동해야 하므로 O(n)입니다.
ArrayList는 내부 배열이 꽉 차면 1.5배 크기의 새 배열을 할당하고 복사합니다. add()의 분할 상환 복잡도는 O(1)입니다.
정렬된 배열에서는 이진 탐색으로 O(log n) 탐색이 가능합니다.
연결 리스트는 이진 탐색 불가능(임의 접근 없음)합니다.

Java — 연결 리스트 직접 구현 vs LinkedList

/* ── 단순 연결 리스트 노드 ──────────────────────────────── */
class Node<T> {
    T data;
    Node<T> next;
    Node(T data) { this.data = data; }
}

/* ── 중간 삽입: O(1) — 포인터 교환만 필요 ──────────────── */
public void insertAfter(Node<Integer> prev, int val) {
    Node<Integer> newNode = new Node<>(val);
    newNode.next = prev.next;  // 새 노드가 다음 노드 가리킴
    prev.next    = newNode;    // 이전 노드가 새 노드 가리킴
    // 포인터 2번 변경으로 완료 — 원소 이동 없음
}

/* ── 탐색: O(n) — 순차 순회 필요 ───────────────────────── */
public Node<Integer> findNode(Node<Integer> head, int val) {
    Node<Integer> cur = head;
    while (cur != null) {
        if (cur.data == val) return cur;
        cur = cur.next;
    }
    return null;
}

/* ── Java LinkedList — 이중 연결 리스트 ─────────────────── */
LinkedList<Integer> linked = new LinkedList<>();
linked.addFirst(10);             // O(1) — head 포인터 변경
linked.addLast(50);              // O(1) — tail 포인터 변경
linked.add(1, 20);               // O(n) 탐색 + O(1) 삽입
linked.get(2);                   // O(n) — 순차 탐색
linked.removeFirst();             // O(1) — head 포인터 변경

/* ── Deque로 사용 시 — 양끝 O(1) ───────────────────────── */
Deque<Integer> deque = new LinkedList<>();
deque.offerFirst(1);             // 앞에 추가
deque.offerLast(2);              // 뒤에 추가
deque.pollFirst();               // 앞에서 제거

연결 리스트 삽입·삭제는 포인터 2개만 바꾸면 되므로 위치를 알고 있을 때 O(1)입니다.
단, 삽입 위치까지 탐색하는 과정이 O(n)이므로 전체 복잡도는 탐색+삽입입니다.
Java의 LinkedList는 이중 연결 리스트로 prev·next 포인터를 모두 갖습니다. head/tail 포인터도 유지해 맨 앞/뒤 삽입·삭제는 O(1)입니다.
임의 접근(get(i))은 O(n)이므로 인덱스 기반 조회가 많다면 ArrayList가 훨씬 유리합니다.
실무에서 LinkedList가 가장 빛나는 용도는 양끝 삽입/삭제가 빈번한 Deque 구현입니다.
