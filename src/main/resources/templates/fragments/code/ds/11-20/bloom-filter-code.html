Python — 블룸 필터 기본 구현

def djb2(s):
    h = 5381
    for c in s.encode():
        h = (h * 33 + c) & 0xFFFFFFFF
    return h

def fnv(s):
    h = 0x811c9dc5
    for c in s.encode():
        h ^= c
        h = (h * 0x01000193) & 0xFFFFFFFF
    return h

class BloomFilter:
    def __init__(self, m, k):
        self.m, self.k = m, k
        self.bits = [0] * m

    def _positions(self, item):
        a, b = djb2(item), fnv(item) | 1      # 이중 해싱: h_i = a + i*b
        return [(a + i * b) % self.m for i in range(self.k)]

    def add(self, item):
        for p in self._positions(item):
            self.bits[p] = 1

    def might_contain(self, item):
        return all(self.bits[p] for p in self._positions(item))

bf = BloomFilter(16, 3)
for w in ['apple', 'banana', 'cherry']:
    bf.add(w)
print(bf._positions('apple'), sum(bf.bits))                 # [7, 6, 5] 7
print(bf.might_contain('apple'), bf.might_contain('mango'), bf.might_contain('grape'))   # True False True

비트 배열 하나와 해시 위치 k개를 구하는 함수만 있으면 됩니다. 여기서는 해시 함수를 k개 따로 만드는 대신, 서로 다른 해시 두 개(djb2와 FNV)로 a + i * b를 계산하는 이중 해싱으로 위치 3개를 만듭니다. b를 홀수로 만들어 칸 수가 2의 거듭제곱일 때 위치가 겹치지 않게 합니다. add는 위치의 칸을 1로 켜고, might_contain은 위치의 칸이 모두 1인지 확인합니다. 이름이 contain이 아니라 might_contain인 이유는 "모두 1"이어도 다른 원소가 켠 칸일 수 있기 때문입니다. apple, banana, cherry를 넣은 뒤 apple의 위치는 7, 6, 5이고 켜진 칸은 7개입니다. mango는 12와 1이 0이라 False(확실히 없음)이고, 추가한 적 없는 grape는 위치 4, 5, 6이 모두 켜져 있어 True가 나옵니다. 시각화의 조회 탭이 보여 주는 거짓 양성입니다.

Python — 크기 계산과 실제 거짓 양성률

import math

def size(n, p):
    m = math.ceil(-n * math.log(p) / (math.log(2) ** 2))   # 비트 수
    k = round(m / n * math.log(2))                           # 해시 함수 수
    return m, k

m, k = size(1_000_000, 0.01)
print(m, k, round(m / 8 / 1024))      # 9585059 7 1170  (약 1.14MiB)

n = 10000
m, k = size(n, 0.01)
bf = BloomFilter(m, k)
for i in range(n):
    bf.add('item-%d' % i)
print(all(bf.might_contain('item-%d' % i) for i in range(n)))     # True (거짓 음성 없음)
fp = sum(bf.might_contain('other-%d' % i) for i in range(100000))
print(m, k, fp / 100000)                          # 95851 7 0.00972

원소 수 n과 목표 거짓 양성률 p가 정해지면 필요한 비트 수는 m = -n ln p / (ln 2)^2, 최적의 해시 함수 수는 k = (m / n) ln 2로 계산합니다. 원소 100만 개를 1% 오류율로 담으려면 비트 약 958만 개, 즉 약 1.14MiB가 필요하고 해시 함수는 7개입니다. 원소 하나당 약 9.6비트입니다. 원소 1만 개로 실제로 만들어 확인하면, 넣은 원소는 모두 "있을 수도 있다"로 나오고(거짓 음성 없음), 넣지 않은 10만 개 가운데 0.97%가 거짓 양성으로 나왔습니다. 목표한 1%에 가깝습니다. 이 예의 문자열(item-숫자)을 그대로 저장하면 글자만 약 89KB이지만, 블룸 필터는 약 12KB면 됩니다. 원소 자체를 저장하지 않는다는 점이 공간 절약의 원천입니다.

Python — 삭제가 되는 Counting Bloom Filter

class CountingBloomFilter(BloomFilter):
    def add(self, item):
        for p in self._positions(item):
            self.bits[p] += 1                  # 비트 대신 카운터를 올린다

    def remove(self, item):
        for p in self._positions(item):
            self.bits[p] -= 1                  # 지울 때는 카운터를 내린다

cbf = CountingBloomFilter(16, 3)
for w in ['apple', 'banana', 'cherry']:
    cbf.add(w)
cbf.remove('apple')
print(cbf.might_contain('apple'), cbf.might_contain('banana'))   # False True

Counting Bloom Filter는 칸마다 비트 하나 대신 작은 카운터를 두어 삭제를 지원합니다. add는 위치의 카운터를 1씩 올리고 remove는 1씩 내리며, might_contain은 카운터가 0보다 큰지 확인합니다. 파이썬 코드에서는 부모 클래스의 might_contain이 값이 0이 아닌지 검사하므로 그대로 쓸 수 있습니다. 앞에서 본 문제 상황과 같은 apple, banana, cherry에서 apple을 지워도, 칸 6과 7은 banana도 쓰고 있어 카운터가 2에서 1로 내려갈 뿐 0이 되지 않습니다. 그래서 banana는 여전히 True이고 apple은 False입니다. 비트 필터에서는 이 두 칸이 0이 되어 banana가 거짓 음성이 되었습니다. 대신 칸당 메모리가 비트 1개에서 카운터로 늘어납니다. 카운팅 블룸 필터를 제안한 Fan 등의 분석은 칸당 4비트면 오버플로 확률이 극히 낮아 충분하다고 봅니다. 같은 원소를 추가한 적 없이 remove하면 카운터가 음수가 될 수 있어서, 실제로 있었던 원소만 지운다는 전제가 필요합니다. 없던 원소를 지우면 공유한 칸의 카운터가 줄어 다른 원소의 거짓 음성이 생길 수도 있습니다.
