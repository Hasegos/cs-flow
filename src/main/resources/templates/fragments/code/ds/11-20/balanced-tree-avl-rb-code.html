Python — AVL 트리 삽입과 회전

class Node:
    def __init__(self, key):
        self.key, self.left, self.right, self.h = key, None, None, 1

def h(n): return n.h if n else 0
def update(n): n.h = 1 + max(h(n.left), h(n.right))
def balance(n): return h(n.left) - h(n.right)    # 균형 인수

def rotate_right(z):
    y = z.left
    z.left, y.right = y.right, z
    update(z); update(y)
    return y                          # 서브트리의 새 루트

def rotate_left(z):
    y = z.right
    z.right, y.left = y.left, z
    update(z); update(y)
    return y

def insert(n, key):
    if not n: return Node(key)
    if key < n.key: n.left = insert(n.left, key)
    else: n.right = insert(n.right, key)
    update(n)
    b = balance(n)
    if b > 1:                                  # 왼쪽이 무거움
        if balance(n.left) < 0: n.left = rotate_left(n.left)    # LR: 먼저 왼쪽 회전
        return rotate_right(n)
    if b < -1:                                 # 오른쪽이 무거움
        if balance(n.right) > 0: n.right = rotate_right(n.right)  # RL: 먼저 오른쪽 회전
        return rotate_left(n)
    return n

root = None
for k in [10, 20, 30, 40, 50, 25]:
    root = insert(root, k)
print(root.key, root.left.key, root.right.key)   # 30 20 40

각 노드는 서브트리의 높이 h를 저장하고, 균형 인수(왼쪽 높이 - 오른쪽 높이)가 1보다 크거나 -1보다 작아지면 회전으로 복구합니다. 균형 인수가 2이고 왼쪽 자식이 왼쪽으로 기운 경우는 오른쪽 회전 한 번(LL), 왼쪽 자식이 오른쪽으로 기운 경우는 왼쪽 자식을 먼저 왼쪽 회전한 뒤 오른쪽 회전(LR)입니다. 오른쪽 방향은 대칭입니다. 재귀로 삽입한 뒤 돌아오면서 경로의 노드마다 높이를 갱신하고 균형을 검사하므로, 불균형이 생긴 가장 아래 노드에서 회전하면 위쪽은 자동으로 균형이 복구됩니다. 회전은 포인터 몇 개를 바꾸는 O(1) 작업입니다. 키 10, 20, 30, 40, 50, 25를 넣으면 시각화의 AVL 탭과 같이 루트 30, 왼쪽 자식 20, 오른쪽 자식 40이 됩니다. 삭제도 같은 회전으로 복구하지만 위쪽까지 여러 번 회전이 필요할 수 있어 이 코드에는 넣지 않았습니다.

Python — 정렬된 입력에서 BST와 AVL의 높이

def bst_insert(n, key):          # 균형을 맞추지 않는 일반 삽입
    if not n: return Node(key)
    if key < n.key: n.left = bst_insert(n.left, key)
    else: n.right = bst_insert(n.right, key)
    update(n)
    return n

plain = avl = None
for k in range(1, 16):          # 1, 2, ..., 15를 정렬된 순서로
    plain = bst_insert(plain, k)
    avl = insert(avl, k)
print(h(plain), h(avl))        # 15 4

같은 Node와 update를 쓰되 회전을 하지 않는 삽입 함수를 하나 더 만들어, 1부터 15까지 정렬된 순서로 넣었을 때의 높이를 비교합니다. 일반 이진 탐색 트리는 모든 키가 오른쪽으로 이어져 높이가 15인 연결 리스트가 되고, AVL 트리는 회전으로 높이 4를 유지합니다. 탐색은 높이만큼 비교하므로 일반 트리에서는 최대 15번, AVL에서는 최대 4번입니다. 키가 100만 개이면 이 차이는 100만 번 대 약 20번(정렬된 입력일 때 AVL의 높이)으로 벌어집니다. 시각화의 높이 비교 탭이 보여 주는 값(15와 4)과 같습니다. 레드-블랙 트리도 같은 입력에서 높이 O(log n)을 유지합니다.

Java — TreeMap(레드-블랙 트리 기반) 사용

import java.util.TreeMap;

TreeMap<Integer, String> map = new TreeMap<>();
map.put(30, "c"); map.put(10, "a"); map.put(20, "b");

System.out.println(map.firstKey());      // 10  (가장 작은 키)
System.out.println(map.floorKey(25));    // 20  (25 이하 중 가장 큰 키)
System.out.println(map.ceilingKey(25));  // 30  (25 이상 중 가장 작은 키)
System.out.println(map.headMap(30));     // {10=a, 20=b}  (30 미만)

자바의 TreeMap은 레드-블랙 트리를 바탕으로 한 NavigableMap으로, put, get, remove가 O(log n)에 동작하고 키를 정렬된 순서로 유지합니다. 직접 균형을 맞추는 코드를 쓰지 않아도 레드-블랙 트리의 이점을 그대로 얻습니다. 해시 맵과 달리 정렬된 순서를 알기 때문에 floorKey, ceilingKey, headMap 같은 범위 질의를 쓸 수 있습니다. 25 이하에서 가장 큰 키를 O(log n)에 찾는 일은, 해시 맵으로는 전체를 훑어야 해서 O(n)이 걸립니다. 정렬이나 범위 검색이 필요 없다면 해시 맵이 평균 O(1)로 더 빠르므로, 순서가 필요한 곳에 TreeMap을 고르는 것이 일반적입니다.
