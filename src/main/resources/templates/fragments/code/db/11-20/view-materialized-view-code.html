SQL — PostgreSQL의 뷰와 구체화 뷰

CREATE VIEW region_sales AS
SELECT region, SUM(amount) AS total FROM orders GROUP BY region;
SELECT * FROM region_sales;                           -- 조회할 때마다 위 쿼리가 원본에 실행된다

CREATE MATERIALIZED VIEW region_mv AS
SELECT region, SUM(amount) AS total FROM orders GROUP BY region
WITH DATA;                                          -- 만들 때 결과를 채운다 (기본값)

CREATE UNIQUE INDEX ON region_mv (region);               -- CONCURRENTLY 갱신에 필요

REFRESH MATERIALIZED VIEW region_mv;                    -- 갱신 동안 조회가 막힐 수 있다
REFRESH MATERIALIZED VIEW CONCURRENTLY region_mv;      -- 조회를 막지 않고 갱신

SELECT matviewname, ispopulated FROM pg_matviews;     -- 구체화 뷰 목록과 채워졌는지 여부

일반 뷰는 CREATE VIEW로 쿼리에 이름을 붙여 저장하고, 조회할 때마다 그 쿼리를 원본 테이블에 실행합니다. 구체화 뷰는 CREATE MATERIALIZED VIEW가 쿼리를 한 번 실행해 결과를 실제 데이터로 저장하며, 원본이 바뀌어도 자동으로 반영되지 않고 REFRESH로 갱신해야 합니다. 시각화의 일반 뷰와 구체화 뷰 탭이 보여 주는 차이와 같습니다. REFRESH MATERIALIZED VIEW는 옵션 없이 쓰면 갱신하는 동안 조회를 막을 수 있고, CONCURRENTLY를 붙이면 조회를 막지 않고 갱신하지만 구체화 뷰에 컬럼만으로 만든(표현식과 WHERE가 없는) UNIQUE 인덱스가 있어야 하고 이미 채워진 상태여야 합니다. 시각화의 REFRESH 탭이 보여 주는 동작입니다. 자세한 문법과 제약은 PostgreSQL 문서를 확인하세요.

Python — 조회마다 계산하는 뷰와 저장된 구체화 뷰

base = [('KR', 100), ('KR', 200), ('US', 150), ('KR', 50), ('US', 300), ('JP', 80)]
reads = 0

def query():                                  # 지역별 합계 쿼리
    global reads
    reads += len(base)                        # 원본에서 읽은 행 수
    out = {}
    for region, amount in base:
        out[region] = out.get(region, 0) + amount
    return out

def view():                                   # 일반 뷰: 조회할 때마다 쿼리 실행
    return query()

stored = query()                              # 구체화 뷰: 만들 때 한 번 실행해 저장

def mview():
    return stored                             # 조회는 저장된 결과를 읽음

def refresh():
    global stored
    stored = query()                          # REFRESH: 쿼리를 다시 실행해 저장

reads = 0
base.append(('KR', 150))                      # 원본에 새 행
print('뷰', view()['KR'], '읽은 행', reads)
print('구체화 뷰', mview()['KR'], '읽은 행', reads)
refresh()
print('REFRESH 뒤', mview()['KR'], '읽은 행', reads)
# 뷰 500 읽은 행 7
# 구체화 뷰 350 읽은 행 7
# REFRESH 뒤 500 읽은 행 14

두 방식의 차이를 읽은 행 수로 보여 주는 장난감 모델입니다. 원본에 KR 150 행을 추가한 뒤 뷰를 조회하면 쿼리가 원본 7행을 읽어 최신 합계 500을 돌려줍니다. 구체화 뷰는 저장된 결과를 읽을 뿐이라 읽은 행이 늘지 않고, 값은 갱신 전의 350 그대로입니다. REFRESH가 쿼리를 다시 실행해 원본 7행을 더 읽으면 총 14행이 되고 값이 500으로 바뀝니다. 시각화의 구체화 뷰 탭과 같은 흐름입니다. 구체화 뷰의 조회가 가볍다는 것은 저장된 결과를 읽기만 하기 때문이고, 그 대가가 갱신 전까지 오래된 값을 읽는 것입니다.

Java — 같은 모델을 자바로

static List<Map.Entry<String, Integer>> base = new ArrayList<>(List.of(
    Map.entry("KR", 100), Map.entry("KR", 200), Map.entry("US", 150),
    Map.entry("KR", 50), Map.entry("US", 300), Map.entry("JP", 80)));
static int reads = 0;
static Map<String, Integer> stored;

static Map<String, Integer> query() {
    reads += base.size();
    Map<String, Integer> out = new TreeMap<>();
    for (Map.Entry<String, Integer> e : base) out.merge(e.getKey(), e.getValue(), Integer::sum);
    return out;
}

stored = query();                                  // 구체화 뷰를 만들 때 한 번 실행
reads = 0;
base.add(Map.entry("KR", 150));
System.out.println("뷰 " + query().get("KR") + " 읽은 행 " + reads);      // 뷰 500 읽은 행 7
System.out.println("구체화 뷰 " + stored.get("KR") + " 읽은 행 " + reads);  // 구체화 뷰 350 읽은 행 7
stored = query();                                  // REFRESH
System.out.println("REFRESH 뒤 " + stored.get("KR") + " 읽은 행 " + reads);  // REFRESH 뒤 500 읽은 행 14

파이썬 모델과 같은 흐름을 자바로 옮긴 코드로 출력도 같습니다. 아래 조각은 main 메서드 안에서 실행한다고 가정했습니다. query가 조회마다 원본 행을 모두 읽어 합계를 구하고, 구체화 뷰에 해당하는 stored는 만들 때 한 번 채워 둔 결과를 그대로 돌려줍니다. 원본에 행이 늘어난 뒤에도 stored는 REFRESH에 해당하는 query 재실행 전까지 350입니다. 실제 데이터베이스는 이렇게 애플리케이션 코드에서 구체화하지 않고 구체화 뷰를 SQL 객체로 제공합니다. 일반 뷰의 쿼리 재작성, 구체화 뷰의 저장과 갱신은 모두 데이터베이스가 처리합니다. 이 코드는 개념 설명용입니다.
