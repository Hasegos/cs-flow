SQL — OLTP의 트랜잭션과 OLAP의 집계 쿼리

-- OLTP: 짧은 트랜잭션, 행 하나씩
BEGIN;
INSERT INTO sales (id, sold_on, region, product, amount)
VALUES (7, '2024-10-04', 'KR', 'A', 120);
UPDATE stock SET quantity = quantity - 1 WHERE product = 'A';
COMMIT;

SELECT * FROM sales WHERE id = 7;                    -- 기본 키 인덱스를 써서 행 하나를 찾을 수 있다

-- OLAP: 많은 행을 훑어 집계
SELECT region, date_trunc('month', sold_on) AS month, SUM(amount) AS total
FROM sales
WHERE sold_on >= '2022-01-01'
GROUP BY region, month
ORDER BY region, month;                              -- 지난 몇 해의 지역별 월 매출

위쪽은 OLTP의 전형적인 모습입니다. 주문 한 건을 INSERT하고 재고를 UPDATE한 뒤 바로 커밋하는 짧은 트랜잭션이고, 조회도 기본 키 인덱스를 써서 행 하나를 찾을 수 있습니다. 시각화의 OLTP 탭이 보여 주는 INSERT, UPDATE, SELECT와 같은 흐름이며, 시각화는 표의 행 하나를 예로 강조합니다. date_trunc와 GROUP BY에서 출력 열 별칭을 쓰는 것은 PostgreSQL 기준 문법이고 제품마다 다릅니다. 아래쪽은 OLAP의 전형적인 모습입니다. 오랜 기간의 많은 행을 훑어 지역과 월별로 묶어 합계를 구합니다. 결과는 요약된 소수의 행이지만 읽는 행은 매우 많아 쿼리 하나가 오래 걸릴 수 있어, 업무 처리용 DB와 분리한 데이터 웨어하우스에서 돌리는 경우가 많습니다. 테이블과 열 이름은 예시입니다.

Python — 행 지향과 컬럼 지향이 읽는 양

rows = [(1, '10-01', 'KR', 'A', 100), (2, '10-01', 'US', 'B', 150), (3, '10-02', 'KR', 'A', 200),
        (4, '10-02', 'JP', 'C', 80), (5, '10-03', 'US', 'B', 300), (6, '10-03', 'KR', 'A', 50)]
names = ('id', 'date', 'region', 'product', 'amount')

cols = {n: [r[i] for r in rows] for i, n in enumerate(names)}   # 컬럼 지향: 열마다 모아 저장

need = ('region', 'amount')                                      # 집계 쿼리가 필요한 열
row_cells = len(rows) * len(names)                               # 행 지향: 행 전체를 읽음
col_cells = len(rows) * len(need)                                # 컬럼 지향: 필요한 열만 읽음
print('읽는 셀:', row_cells, col_cells)

total = {}
for region, amount in zip(cols['region'], cols['amount']):
    total[region] = total.get(region, 0) + amount
print('집계:', total)

print('행 하나(id=3) 읽기:', rows[2])                            # 행 지향: 한 번에 연속으로
print('컬럼 지향으로 id=3 읽기:', [cols[n][2] for n in names], '열 5곳을 읽음')
# 읽는 셀: 30 12
# 집계: {'KR': 350, 'US': 450, 'JP': 80}
# 행 하나(id=3) 읽기: (3, '10-02', 'KR', 'A', 200)
# 컬럼 지향으로 id=3 읽기: [3, '10-02', 'KR', 'A', 200] 열 5곳을 읽음

같은 6행을 행 지향(rows)과 컬럼 지향(cols)으로 놓고 읽는 양을 비교하는 장난감 모델입니다. 지역별 합계에는 region과 amount 두 열만 필요하므로, 컬럼 지향은 12칸만 읽고 행 지향은 행 전체인 30칸을 읽습니다. 시각화의 행 vs 컬럼 저장 탭과 같은 결과입니다. 집계 결과는 KR 350, US 450, JP 80입니다. 반대로 id가 3인 행 하나를 읽는 경우, 행 지향은 한 곳에서 5개의 값을 한꺼번에 읽지만 컬럼 지향은 5개의 열을 각각 찾아가야 합니다. 실제 컬럼 지향 저장소는 열을 압축하고 블록 단위로 읽으며 훨씬 복잡합니다.

Java — 스트림 집계와 열 단위 배열

record Sale(int id, String date, String region, String product, int amount) {}

List<Sale> rows = List.of(
    new Sale(1, "10-01", "KR", "A", 100), new Sale(2, "10-01", "US", "B", 150),
    new Sale(3, "10-02", "KR", "A", 200), new Sale(4, "10-02", "JP", "C", 80),
    new Sale(5, "10-03", "US", "B", 300), new Sale(6, "10-03", "KR", "A", 50));

Map<String, Integer> byRegion = rows.stream()
    .collect(Collectors.groupingBy(Sale::region, TreeMap::new, Collectors.summingInt(Sale::amount)));
System.out.println("집계: " + byRegion);                           // 집계: {JP=80, KR=350, US=450}

int[] amount = rows.stream().mapToInt(Sale::amount).toArray();      // 컬럼 지향: amount 열만 모은 배열
System.out.println("amount 열: " + Arrays.toString(amount) + " 합계 " + Arrays.stream(amount).sum());
// amount 열: [100, 150, 200, 80, 300, 50] 합계 880

자바에서는 레코드 목록(행 지향)에 스트림으로 groupingBy와 summingInt를 적용해 지역별 합계를 구합니다. TreeMap을 써서 키 순서로 JP, KR, US가 출력되고 값은 파이썬 결과와 같습니다. 이 방식은 Sale 객체를 하나씩 따라가며 region과 amount를 읽습니다. 아래쪽처럼 amount만 모은 배열로 합계를 구하면 필요한 열만 읽는 컬럼 지향의 모습을 흉내 낼 수 있고, 합계 880은 세 지역의 합 350 + 450 + 80과 같습니다. 많은 분석 엔진은 열 단위 저장과 압축을 쓰고, 일부는 벡터화된 계산도 함께 씁니다. 이 코드는 개념 설명용입니다.
