SQL — 기본키(PK) / 외래키(FK) 정의

-- USERS: id를 기본키로 지정 (자동 증가)
CREATE TABLE users (
    id     BIGINT       PRIMARY KEY AUTO_INCREMENT,
    name   VARCHAR(50)  NOT NULL,
    email  VARCHAR(100) NOT NULL
);

-- ORDERS: user_id를 외래키로 지정 (USERS.id를 참조)
CREATE TABLE orders (
    id        BIGINT      PRIMARY KEY AUTO_INCREMENT,
    user_id   BIGINT      NOT NULL,
    product   VARCHAR(50) NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

PRIMARY KEY는 id가 유일하고(UNIQUE) 비어있지 않음(NOT NULL)을 DB 차원에서 보장합니다.
FOREIGN KEY ... REFERENCES는 orders.user_id에 users.id에 없는 값을 넣으려는 시도를 DB가 직접 거부하게 만듭니다 — 시각화의 "외래키 관계" 탭에서 본 거부 동작이 바로 이 제약 조건입니다.

Java — JPA Entity로 기본키 / 외래키 표현

@Entity
@Table(name = "users")
@Getter
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // 기본키 — DB가 자동 채번
    private Long id;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false)
    private String email;
}

@Entity
@Table(name = "orders")
@Getter
public class Order {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", nullable = false)   // 외래키 — USERS.id 참조
    private User user;

    @Column(nullable = false)
    private String product;
}

User.id는 @Id + @GeneratedValue로 기본키를, Order.user는 @JoinColumn(name = "user_id")로 외래키를 표현합니다.
객체지향 코드에서는 숫자 id 대신 User user 필드를 직접 들고 있는 것처럼 보이지만, 실제 테이블에는 SQL 예시와 동일하게 user_id 컬럼(외래키 값)만 저장됩니다.

Java — 기본키로 조회하기 (Repository / Service)

public interface OrderRepository extends JpaRepository<Order, Long> {

    // LEFT JOIN FETCH: 연관된 User를 한 번에 가져와 LazyInitializationException 방지
    @Query("SELECT o FROM Order o LEFT JOIN FETCH o.user WHERE o.id = :id")
    Optional<Order> findByIdWithUser(@Param("id") Long id);
}

@Service
@RequiredArgsConstructor
@Transactional
public class OrderService {

    private final OrderRepository orderRepository;

    public Order getOrder(Long id) {
        return orderRepository.findByIdWithUser(id)
                .orElseThrow(() -> new NotFoundException("주문을 찾을 수 없습니다: id=" + id));
    }
}

기본키(id)로 조회할 땐 결과가 없을 수도 있으므로 Optional로 감싸고, Optional.get() 대신 orElseThrow()로 없을 경우를 명시적으로 처리합니다.
LEFT JOIN FETCH로 외래키가 가리키는 User까지 한 번의 쿼리로 함께 가져오는 것이 이 프로젝트의 표준 패턴입니다.
