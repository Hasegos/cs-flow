리눅스 — 출발지 NAT(MASQUERADE)로 내부망 공유

# 이 장비가 패킷을 전달(라우팅)하도록 켜기
sudo sysctl -w net.ipv4.ip_forward=1

# eth0(외부 쪽)으로 나가는 패킷의 출발지를 eth0의 주소로 바꾸기
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# nat 표의 규칙 확인
sudo iptables -t nat -L -n -v

리눅스를 공유기처럼 쓰려면 먼저 ip_forward로 패킷 전달을 켭니다. nat 표의 POSTROUTING 사슬은 패킷이 나가기 직전에 적용되고, MASQUERADE 대상은 출발지 주소를 나가는 인터페이스(여기서는 eth0)의 현재 주소로 바꿉니다. MASQUERADE는 출발지 주소를 나가는 인터페이스 주소로 바꾸며, 여러 내부 호스트의 포트가 겹치면 포트도 바꿔 PAT처럼 동작합니다. 외부 주소가 DHCP로 바뀌는 환경에서 편리합니다. 주소가 고정이면 SNAT 대상으로 직접 지정할 수도 있습니다. -o eth0 같은 인터페이스 이름은 환경에 맞게 바꿔야 하고, 위 명령은 재부팅하면 사라지므로 영구 설정은 배포판의 방법을 따라야 합니다.

리눅스 — 포트 포워딩(DNAT)과 변환 표 확인

# 공인 쪽 8080 포트로 오는 TCP를 내부 192.168.0.20:80으로 보내기
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 \
    -j DNAT --to-destination 192.168.0.20:80

# 연결 추적 표 보기 (conntrack 도구 필요)
sudo conntrack -L

nat 표의 PREROUTING 사슬은 패킷이 들어오자마자 적용되어, DNAT 대상이 목적지를 내부 서버의 주소와 포트로 바꿉니다. 응답 패킷의 출발지는 커널의 연결 추적이 자동으로 되돌려 주므로 응답 방향 규칙은 따로 쓰지 않습니다. conntrack -L은 커널이 기억하고 있는 연결 목록을 보여 주며, 각 항목에 원래 방향과 응답 방향의 주소 · 포트가 함께 나와 NAT가 어떻게 바꿨는지 확인할 수 있습니다. 포워딩된 패킷이 통과하도록 FORWARD 사슬의 규칙이 막지 않는지도 확인해야 하며, 위 코드는 개념을 보이는 최소 예시입니다.

Python — PAT 변환 표 흉내 내기

class Nat:
    def __init__(self, public_ip, first_port=40001):
        self.public_ip = public_ip
        self.next_port = first_port
        self.out = {}    # (내부 IP, 내부 포트) -> 외부 포트
        self.back = {}   # 외부 포트 -> (내부 IP, 내부 포트)

    def outbound(self, src_ip, src_port):
        key = (src_ip, src_port)
        if key not in self.out:
            self.out[key] = self.next_port
            self.back[self.next_port] = key
            self.next_port += 1
        return self.public_ip, self.out[key]

    def inbound(self, dst_port):
        return self.back.get(dst_port)   # 표에 없으면 None (버림)

nat = Nat("203.0.113.5")
print(nat.outbound("192.168.0.10", 51000))   # ('203.0.113.5', 40001)
print(nat.outbound("192.168.0.20", 51000))   # ('203.0.113.5', 40002)
print(nat.inbound(40001))                    # ('192.168.0.10', 51000)
print(nat.inbound(40009))                    # None

이 클래스는 PAT의 핵심인 변환 표를 딕셔너리 두 개로 흉내 냅니다. outbound는 안에서 밖으로 나가는 연결에 새 외부 포트를 할당하고 표에 기록하며, 이미 있는 연결이면 같은 외부 포트를 다시 씁니다. inbound는 들어오는 패킷의 목적지 포트로 표를 찾아 원래의 내부 주소와 포트를 돌려주고, 표에 없으면 None을 돌려줍니다. 시각화에서 외부의 먼저 시작한 접속이 버려지는 이유입니다. 실제 NAT는 프로토콜별 상태 추적, 항목 만료, 포트 재사용 같은 처리가 더 있으므로 이 코드는 원리만 보이는 최소 예시입니다.
