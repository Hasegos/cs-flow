Python — UDP 멀티캐스트 송신과 수신 (그룹 가입)

import socket, struct

GROUP, PORT = "239.1.2.3", 5007

# 수신: 그룹에 가입하면 호스트가 IGMP 가입 보고를 보낸다
rx = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
rx.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
rx.bind(("", PORT))
mreq = struct.pack("4s4s", socket.inet_aton(GROUP), socket.inet_aton("0.0.0.0"))
rx.setsockopt(socket.IPPROTO_IP, socket.IP_ADD_MEMBERSHIP, mreq)
data, addr = rx.recvfrom(1024)

# 송신: 그룹 주소로 한 번만 보낸다
tx = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
tx.setsockopt(socket.IPPROTO_IP, socket.IP_MULTICAST_TTL, 2)
tx.sendto(b"hello group", (GROUP, PORT))

수신 쪽은 UDP 소켓을 만들어 포트에 묶은 뒤, IP_ADD_MEMBERSHIP 옵션으로 그룹 239.1.2.3에 가입합니다. 이 옵션을 설정하면 운영체제가 네트워크에 IGMP 멤버십 보고를 보내 시각화의 그룹 가입 탭과 같은 가입이 이루어집니다. 송신 쪽은 그룹 주소와 포트로 한 번만 보내면 되고, 받는 호스트가 몇 대든 송신 코드는 같습니다. IP_MULTICAST_TTL은 패킷의 TTL(라우터를 지날 때마다 1씩 감소)을 정하며, 기본값 1은 라우터를 넘지 못해 같은 네트워크 안에서만 전달됩니다. 멀티캐스트는 TCP로 쓸 수 없고 보통 UDP로 보내므로 손실된 데이터를 자동으로 다시 보내 주지 않아, 필요하면 애플리케이션이 따로 처리해야 합니다. 위 코드는 수신(rx)과 송신(tx) 프로세스를 따로 실행해야 하며, 한 스크립트로 이어 실행하면 recvfrom에서 멈춥니다.

Python, tcpdump — 브로드캐스트 송신과 관찰

import socket

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)   # 브로드캐스트 허용
s.sendto(b"who is there?", ("255.255.255.255", 9999))

# 터미널에서 브로드캐스트 / 멀티캐스트 프레임만 관찰하기
sudo tcpdump -i eth0 -n 'ether broadcast'
sudo tcpdump -i eth0 -n 'ip multicast'

UDP 소켓에서 브로드캐스트를 보내려면 SO_BROADCAST 옵션을 켜야 합니다. 목적지 255.255.255.255는 제한된 브로드캐스트 주소로 같은 네트워크 안의 모든 호스트에 전달되고 라우터를 넘지 않습니다. tcpdump의 ether broadcast 필터는 목적지가 브로드캐스트인 이더넷 프레임을, ip multicast 필터는 멀티캐스트 목적지의 IP 패킷을 보여 줍니다. ether broadcast 필터에는 ARP 요청과 DHCP Discover 같은 브로드캐스트 프레임이 잡힙니다. 브로드캐스트는 같은 네트워크의 모든 호스트가 받아 처리해야 하므로 호스트 수가 많을수록 부담이 커지는 방식입니다. 인터페이스 이름(eth0)은 환경마다 다릅니다.

Python — 주소 종류 판별과 멀티캐스트 MAC 계산

import ipaddress

for a in ["192.168.1.10", "192.168.1.255", "239.1.2.3", "224.0.0.1"]:
    print(a, ipaddress.ip_address(a).is_multicast)    # False False True True

net = ipaddress.ip_network("192.168.1.0/24")
print(net.broadcast_address)                          # 192.168.1.255

def mcast_mac(group):
    low23 = int(ipaddress.ip_address(group)) & 0x7FFFFF   # 하위 23비트
    mac = (0x01005E << 24) | low23
    return ":".join(f"{(mac >> s) & 0xFF:02x}" for s in range(40, -1, -8))

print(mcast_mac("239.1.2.3"))                       # 01:00:5e:01:02:03

ipaddress 모듈의 is_multicast는 주소가 멀티캐스트 영역(224.0.0.0/4)에 있는지 알려 주고, 네트워크 객체의 broadcast_address는 서브넷의 마지막 주소인 브로드캐스트 주소를 돌려줍니다. 192.168.1.255는 유니캐스트처럼 보여도 멀티캐스트가 아닙니다. mcast_mac은 그룹 주소의 하위 23비트를 01:00:5e로 시작하는 MAC 주소 뒤에 붙입니다. 239.1.2.3은 01:00:5e:01:02:03이 되며, 시각화의 주소 탭이 보여 주는 값과 같습니다. 그룹 주소의 의미 있는 28비트 중 하위 23비트만 MAC 주소에 담기고 나머지 5비트는 빠집니다. 그래서 224.0.2.3과 224.128.2.3은 둘 다 01:00:5e:00:02:03을 쓰는 식으로, 여러 그룹이 같은 MAC 주소를 공유할 수 있습니다.
